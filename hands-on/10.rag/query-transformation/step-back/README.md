# Step-Back (추상화 질문) RAG 예제

구체적인 질문을 한 단계 추상화한 일반 질문으로 바꿔, 추상 질문과 원본 질문 양쪽으로 검색해 폭넓은 컨텍스트를 확보하는 Query Transformation 기법 예제임.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 기법 | Step-Back Prompting (Query Transformation 계열) |
| 입력 | 공용 벡터 DB: `hands-on/10.rag/vectordb` (컬렉션 `patent_law`, 246개 벡터, 로드만 수행) |
| 임베딩 | OpenAI `text-embedding-3-small` (검색 시 쿼리 임베딩에만 사용) |
| LLM | Groq LPU `openai/gpt-oss-120b` (추상화 질문 생성 + 답변 생성) |
| 핵심 아이디어 | 구체적 질문을 추상 질문으로 한 단계 물러나, 배경 지식 문서까지 함께 검색 |

## 2. 기법 설명

Step-Back Prompting은 구체적인 질문에서 한 단계 뒤로 물러나 더 일반적·추상적인 질문을 생성하는 기법임.  
세부 사례를 다루기 전에 그 사례가 속한 넓은 개념·원칙을 먼저 검색하면, 배경 지식이 담긴 문서까지 확보해 답변의 맥락이 풍부해짐.  
이 예제는 추상화 질문(배경 지식)과 원본 질문(구체 정보) 양쪽으로 검색한 뒤 결과를 합치고 중복을 제거해 상위 5개 청크를 사용함.

변환 예시:

| 구분 | 질문 |
| --- | --- |
| 원본(구체적) | 특허 어떻게 받어? |
| Step-Back(추상적) | 특허를 취득하기 위해 필요한 절차와 요건은 무엇인가요? |

## 3. 처리 흐름

```
원본 질문
   │
   ▼
LLM 추상화 (step_back)  ← 구체적 질문 → 일반적 배경 질문
   │
   ├─────────────┬───────────────┐
   ▼             ▼               
Step-Back 질문 검색   원본 질문 검색   (각 TOP_K=5)
   │             │
   └─────┬───────┘
         ▼
결과 병합 + 중복 제거 (deduplicate_docs) → 상위 5개
         │
         ▼
컨텍스트 주입 (format_docs → SYSTEM_PROMPT)
         │
         ▼
답변 생성 (llm_chain.invoke)
```

## 4. 주요 함수

| 함수 | 역할 |
| --- | --- |
| `load_vectorstore` | 공용 벡터 DB를 재인덱싱 없이 로드함 (컬렉션 `patent_law` 지정) |
| `get_llm` | Groq LPU `openai/gpt-oss-120b` 기반 ChatGroq 인스턴스를 생성함 |
| `step_back` | 구체적 질문을 추상적·일반적 질문으로 변환함 (이 예제의 핵심) |
| `retrieve_with_transformation` | 추상화 질문과 원본 질문으로 각각 검색한 결과를 합치고 중복 제거 후 상위 청크를 반환함 |
| `deduplicate_docs` | 본문이 동일한 중복 문서를 제거해 고유 문서만 남김 |
| `answer_question` | 추상화 → 검색 → 병합 → 컨텍스트 주입 → 답변 생성의 전체 흐름을 수행·출력함 |

### 환경변수

`hands-on/.env`에 아래 키가 필요함.  
- `OPENAI_API_KEY`: 쿼리 임베딩(`text-embedding-3-small`)에 사용  
- `GROQ_API_KEY`: LLM(`openai/gpt-oss-120b`) 추상화 질문·답변 생성에 사용

### 실행 방법

```bash
python app.py                          # 대화형 챗봇 모드
python app.py --demo                   # 기본 테스트 질의어로 one-shot 실행
python app.py --query "특허 어떻게 받어?"  # 지정 질의어로 one-shot 실행
```

**쉬운 설명**  
특허를 받으려면 크게 다음 네 단계 만 알면 됩니다.

1. **출원서 준비**  
   - **누가** 특허를 받고 싶은지(이름·주소, 법인이면 명칭·사업장)와 **대리인**이 있으면 그 사람의 정보도 적어요.  
   - 발명의 **이름**과 **발명자**(누가 만든 사람) 정보를 적어요.  
   - 발명을 **설명**한 상세한 문서(명세서)와 **청구범위**(특허로 보호받고 싶은 내용) 그리고 필요하면 **도면**·요약서를 함께 넣어요.  
   (이 내용은 특허법 제42조에 근거합니다.)

2. **전자·우편·우편 등으로 제출**  
   - 지금은 전자문서로도 제출할 수 있어요. 전자문서는 종이 서류와 같은 효력이 있으니, 인터넷을 통해 특허청(지식재산처)이나 특허심판원에 바로 올리면 됩니다.  
   (전자제출에 관한 규정은 특허법 제28조의3에 근거합니다.)

3. **수수료(료) 납부**  
   - 출원 자체와 심사청구(특허를 심사해 달라는 요청) 등에 필요한 비용을 내야 해요.  
   - 출원인이 아닌 사람이 심사청구를 하면, 청구항이 늘어난 경우에도 추가 비용은 결국 출원인이 부담하게 됩니다.  
   (수수료 관련 규정은 특허법 제82조에 근거합니다.)

4. **심사·결정**  
   - 출원 후에 **심사청구**를 하면, 특허청이 발명이 신규·진보·산업상 이용 가능성 등을 검토합니다.  
   - 심사 결과가 ‘특허 가능’하면 특허가 부여되고, ‘거절’이면 보정(수정)하거나 이의신청·심판을 할 수 있습니다.  

**근거 조문**  
- **특허법 제42조(특허출원)** – 출원서에 들어가야 할 기본 항목과 명세서·청구범위·도면·요약서 등 첨부 서류 요건.  
- **특허법 제28조의3(전자문서에 의한 특허 절차 수행)** – 전자문서 제출이 가능하고, 전자문서는 종이 서류와 동일한 효력을 가진다는 규정.  
- **특허법 제82조(수수료)** – 출원·심사·기타 절차에 필요한 수수료와 납부 방법·기간에 관한 규정.  

**참고사항**  
- **출원 전 준비**: 발명의 기술적 내용이 충분히 명확하고 상세하게 적혀 있어야 심사에서 ‘설명 부족’으로 거절당하지 않습니다.  
- **전문가 도움**: 변리사(특허전문 변호사)에게 초안을 검토받으면 청구범위 작성이 더 정확해져 특허권 범위를 넓게 잡을 수 있습니다.  
- **마감일**: 수수료 납부와 심사청구는 정해진 기간 안에 해야 하며, 기간을 넘기면 출원이 취소될 위험이 있습니다.  
- **전자출원 시**: 제출 후 접수번호를 확인하고, 접수번호를 보관해 두세요. 전자문서는 접수번호가 확인되는 순간에 공식적으로 접수된 것으로 간주됩니다.
