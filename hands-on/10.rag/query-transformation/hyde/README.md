# HyDE (가상 문서 임베딩) RAG 예제

질문 대신 LLM이 만든 가상의 답변 문서를 임베딩해 검색함으로써 질문-문서 형식 차이를 줄여 검색 정확도를 높이는 Query Transformation 기법 예제임.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 기법 | HyDE (Hypothetical Document Embeddings, Query Transformation 계열) |
| 입력 | 공용 벡터 DB: `hands-on/10.rag/vectordb` (컬렉션 `patent_law`, 246개 벡터, 로드만 수행) |
| 임베딩 | OpenAI `text-embedding-3-small` (검색 시 가상 문서 임베딩에만 사용) |
| LLM | Groq LPU `openai/gpt-oss-120b` (가상 답변 생성 + 답변 생성) |
| 핵심 아이디어 | 질문이 아닌 LLM의 '가상 답변'으로 검색해 질문-문서 형식 차이를 완화 |

## 2. 기법 설명

HyDE는 질문을 그대로 검색하지 않고, LLM이 만든 가상의 답변 문서(Hypothetical Document)를 임베딩해 검색하는 기법임.  
짧은 질문 문장보다 답변 형태의 문장이 실제 법령 문서와 어휘·구조가 더 비슷하므로, 가상 답변으로 검색하면 질문-문서 형식 차이를 줄여 검색 정확도가 향상됨.  
가상 답변의 사실 정확성 자체는 중요하지 않으며, 어디까지나 검색을 위한 '미끼' 역할만 함(최종 답변은 실제 검색 청크에 근거해 생성됨).

처리 비교:

| 구분 | 검색에 사용하는 쿼리 |
| --- | --- |
| 일반 검색 | 특허 어떻게 받어? (짧은 구어체 질문) |
| HyDE | LLM이 생성한 가상 답변 문서 (법령 문체의 3~5문장) |

## 3. 처리 흐름

```
원본 질문
   │
   ▼
LLM 가상 답변 생성 (hyde)  ← 법령 문체의 가상 답변 문서
   │
   ▼
가상 문서로 유사도 검색 (retrieve_with_transformation, TOP_K=5)
   │
   ▼
컨텍스트 주입 (format_docs → SYSTEM_PROMPT)
   │
   ▼
답변 생성 (llm_chain.invoke)  ← 실제 검색 청크에 근거
```

## 4. 주요 함수

| 함수 | 역할 |
| --- | --- |
| `load_vectorstore` | 공용 벡터 DB를 재인덱싱 없이 로드함 (컬렉션 `patent_law` 지정) |
| `get_llm` | Groq LPU `openai/gpt-oss-120b` 기반 ChatGroq 인스턴스를 생성함 |
| `hyde` | 질문에 대한 가상의 답변 문서를 생성함 (이 예제의 핵심) |
| `retrieve_with_transformation` | 가상 답변 문서를 쿼리로 사용해 상위 청크를 검색함 |
| `answer_question` | 가상 답변 생성 → 검색 → 컨텍스트 주입 → 답변 생성의 전체 흐름을 수행·출력함 |
| `create_llm_chain` | 프롬프트 → LLM → 문자열 추출로 이어지는 LCEL 답변 체인을 생성함 |

### 환경변수

`hands-on/.env`에 아래 키가 필요함.  
- `OPENAI_API_KEY`: 가상 문서 임베딩(`text-embedding-3-small`)에 사용  
- `GROQ_API_KEY`: LLM(`openai/gpt-oss-120b`) 가상 답변·답변 생성에 사용

### 실행 방법

```bash
python app.py                          # 대화형 챗봇 모드
python app.py --demo                   # 기본 테스트 질의어로 one-shot 실행
python app.py --query "특허 어떻게 받어?"  # 지정 질의어로 one-shot 실행
```

**1. 쉬운 설명**  
특허를 받으려면 다음 순서대로 진행하면 됩니다.

1. **출원 준비**  
   - **출원인(본인)과 발명자 정보** : 이름·주소(법인이면 명칭·본점 주소)  
   - **대리인(변리사) 정보** : 대리인이 있으면 그 사람·사무소 주소(또는 변리사 명)  
   - **발명의 명칭**  
   - **발명 내용** :  
     - **설명서(명세서)** – 발명을 누구라도 이해하고 그대로 만들 수 있게 자세히 적고, 배경 기술도 포함합니다.  
     - **청구범위(청구항)** – “이 발명으로 무엇을 보호하고 싶은가”를 명확하고 간결하게 적습니다. 하나 이상 있어야 합니다.  
     - **도면**(필요한 경우)와 **요약서**(짧게 핵심을 정리)도 함께 첨부합니다.  

2. **출원서 제출**  
   - 위에 적은 서류들을 모두 모아 **지식재산처장**에게 제출합니다. (보통 특허청 전자출원 시스템을 이용합니다.)

3. **심사 과정**  
   - 특허청 심사관이 “거절 사유가 없으면” 특허를 부여합니다. (특허청이 발명의 신규성·진보성·산업적 이용 가능성을 검토합니다.)

4. **특허권 설정·증서 발급**  
   - 심사관이 “특허결정”을 하면, 특허가 **설정등록**됩니다.  
   - 이후 지식재산처장이 특허증을 발급해 줍니다. (특허권을 공식적으로 증명하는 문서)

5. **특허 유지**  
   - 특허가 부여된 뒤에도 매년 특허료를 납부해야 권리를 유지할 수 있습니다.

- **제66조(특허결정)** – 심사관이 거절 사유가 없을 경우 특허결정을 해야 함을 규정.  
- **제86조(특허증의 발급)** – 특허가 설정등록되면 특허증을 발급하도록 규정.

- **전문가(변리사) 활용** : 출원 서류는 형식과 내용이 까다롭기 때문에 변리사의 도움을 받으면 오류를 줄일 수 있습니다.  
- **우선권 주장** : 해외에서 먼저 출원했을 경우, 1년 이내에 국내에 동일 발명을 출원하면 우선권을 주장할 수 있습니다(제55조).  
- **출원 후 포기·무효·취소** : 출원 후 포기하거나 심사 과정에서 거절·무효·취소가 되면 특허를 받을 수 없습니다(제55조·제4조 등).  
- **특허료 납부** : 특허가 부여된 뒤 매년 정해진 기한에 특허료를 납부하지 않으면 권리가 소멸합니다(제85조).
