## 2. 개요

### 2.1 멀티턴 대화 (Multi-turn Conversation)

사용자와 AI가 **맥락(Context)을 유지하면서 여러 번 주고받는 대화 방식**. 단발성 질의응답(싱글턴)과 달리 이전 대화 내용을 기억하고 활용하여 자연스러운 대화 흐름 유지.

### 2.2 싱글턴 vs 멀티턴

| 구분 | 싱글턴 (Single-turn) | 멀티턴 (Multi-turn) |
|------|---------------------|---------------------|
| **대화 방식** | 한 번의 질문-응답으로 종료 | 여러 번의 대화가 이어짐 |
| **맥락 유지** | 없음 | 이전 대화 내용 기억 |
| **정보 수집** | 한 번에 모든 정보 요청 | 점진적으로 정보 수집 |
| **사용 예시** | 단순 질문 답변 | 상담, 예약, 플래닝 |

### 2.3 주요 활용 사례

| 분야 | 설명 |
|------|------|
| **고객 상담 챗봇** | 문의 내용을 대화로 파악하고 맞춤형 응대 제공 |
| **여행/일정 플래너** | 목적지, 기간, 예산 등을 대화로 수집하여 맞춤 일정 생성 |
| **쇼핑 어시스턴트** | 고객 취향을 파악하고 적합한 상품 추천 |
| **교육/튜터링** | 학습자 수준에 맞춘 단계별 설명 제공 |

## 3. 모델 정보

### 3.1 클라이언트 측 컨텍스트 관리

클라이언트가 대화 히스토리를 직접 관리하여 매 API 호출 시 전송하는 방식. **모든 LLM API에서 사용 가능**한 범용 전략.

#### 3.1.1 전체 히스토리 전송

모든 대화 내용을 매번 API에 전송하여 맥락을 유지하는 가장 기본적인 방식.

**특징**
- 구현이 간단하고 정확도 높음
- 대화가 길어지면 토큰 비용 급증
- 컨텍스트 윈도우 한계에 도달 가능
- 10턴 이하의 짧은 대화에 적합

**핵심 코드 (OpenAI)**

```python
from openai import OpenAI

client = OpenAI(api_key="...")

# 대화 히스토리 초기화
messages = [
    {"role": "system", "content": "시스템 프롬프트"}
]

# 대화 루프
while True:
    user_input = input("👤 나: ")
    
    # 사용자 메시지 추가
    messages.append({"role": "user", "content": user_input})
    
    # API 호출 (전체 히스토리 전송!)
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages
    )
    
    # AI 응답 추출 및 히스토리에 추가
    assistant_message = response.choices[0].message.content
    messages.append({"role": "assistant", "content": assistant_message})
```

#### 3.1.2 슬라이딩 윈도우 + 요약

최근 N개의 메시지만 유지하고, 오래된 대화는 AI가 요약하여 압축하는 방식.

**특징**
- 토큰 사용량 최적화
- 긴 대화에서도 맥락 유지 가능
- 요약 품질에 의존
- 구현 복잡
- 10-50턴의 중간 길이 대화에 적합

**핵심 코드**

```python
WINDOW_SIZE = 6       # 최근 유지할 메시지 수
SUMMARY_THRESHOLD = 8 # 요약 시작 기준

def summarize_conversation(messages_to_summarize):
    """오래된 대화를 AI가 요약"""
    summary_response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "대화를 핵심 정보만 추출하여 요약하세요."},
            {"role": "user", "content": f"요약: {messages_to_summarize}"}
        ]
    )
    return summary_response.choices[0].message.content

def build_messages_with_summary(full_history, summary):
    """요약본 + 최근 대화 결합"""
    system_content = BASE_SYSTEM_PROMPT
    if summary:
        system_content += f"\n\n## 이전 대화 요약\n{summary}"
    
    messages = [{"role": "system", "content": system_content}]
    messages.extend(full_history[-WINDOW_SIZE:])  # 최근 대화만 추가
    
    return messages
```

### 3.2 서버 측 상태 관리

플랫폼에서 제공하는 **전용 API**를 사용하여 서버가 대화 상태를 자동 관리하는 방식. 클라이언트 측 히스토리 관리 불필요.

#### 3.2.1 OpenAI Responses API

OpenAI에서 제공하는 최신 Stateful API. `previous_response_id`로 이전 응답을 참조하여 대화 체이닝.

**특징**
- 클라이언트가 히스토리 관리할 필요 없음
- 서버에서 컨텍스트 최적화 자동 수행
- 간결한 코드로 구현 가능
- Response ID 저장으로 대화 이어가기 가능

**제한사항**
- OpenAI 전용 API
- Assistants API는 2025.08.26 deprecated → 2026.08.26 종료

**핵심 코드**

```python
from openai import OpenAI

client = OpenAI(api_key="...")

# 첫 번째 응답
response1 = client.responses.create(
    model="gpt-4o-mini",
    instructions="시스템 프롬프트",
    input="도쿄 여행 계획 세워줘",
    store=True  # 서버에 저장
)

# 두 번째 응답 (체이닝)
response2 = client.responses.create(
    model="gpt-4o-mini",
    instructions="시스템 프롬프트",
    input="3박 4일이요",
    previous_response_id=response1.id,  # 이전 응답 참조!
    store=True
)

print(response2.output_text)
```

#### 3.2.2 Gemini Chat Session

Google에서 제공하는 Chat API. 채팅 세션 객체가 대화 상태를 자동 관리.

**특징**
- `send_message()`로 메시지 전송 시 히스토리 자동 관리
- `get_history()`로 전체 대화 기록 조회 가능
- OpenAI Responses API와 유사한 편리함

**핵심 코드**

```python
from google import genai

client = genai.Client(api_key="...")

# 채팅 세션 생성 (서버가 히스토리 자동 관리!)
chat = client.chats.create(
    model="gemini-2.0-flash",
    config={"system_instruction": "시스템 프롬프트"}
)

# 메시지 전송 (히스토리 자동 추가)
response1 = chat.send_message("도쿄 여행 계획 세워줘")
print(response1.text)

response2 = chat.send_message("3박 4일이요")  # 이전 대화 자동 참조!
print(response2.text)

# 전체 대화 기록 조회
for msg in chat.get_history():
    print(f"{msg.role}: {msg.parts[0].text}")
```

#### 3.2.3 Claude API (클라이언트 방식만 지원)

Anthropic Claude는 서버 측 상태 관리 API 미제공으로 **'전체 히스토리 전송' 또는 '슬라이딩 윈도우+요약' 방식**만 사용 가능.

**특징**
- `system` 파라미터를 messages 배열이 아닌 별도로 전달
- OpenAI Chat Completions API와 유사한 구조
- 긴 대화 시 슬라이딩 윈도우 + 요약 방식 권장

**핵심 코드**

```python
import anthropic

client = anthropic.Anthropic(api_key="...")

# messages 배열로 전체 히스토리 전송
response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    system="시스템 프롬프트",  # 별도 파라미터로 전달!
    messages=[
        {"role": "user", "content": "도쿄 여행 계획 세워줘"},
        {"role": "assistant", "content": "좋아요! 며칠 여행하시나요?"},
        {"role": "user", "content": "3박 4일이요"}
    ]
)

print(response.content[0].text)
```

### 3.3 방식별 비교 정리

프로젝트 상황에 따른 최적 방식 선택 가이드.

| 구분 | 전체 히스토리 | 슬라이딩+요약 | Responses API | Chat Session |
| :--- | :--- | :--- | :--- | :--- |
| **구현 난이도** | ⭐ (쉬움) | ⭐⭐⭐ (복잡) | ⭐ (쉬움) | ⭐ (쉬움) |
| **지원 모델** | **모든 LLM** | **모든 LLM** | OpenAI 전용 | Gemini 전용 |
| **히스토리 관리** | 클라이언트 | 클라이언트 | **서버** | **서버** |
| **토큰 효율** | 낮음 | **높음** | 높음 | 높음 |
| **긴 대화 지원** | 한계 있음 | **우수** | **우수** | **우수** |
| **권장 용도** | 짧은 대화 (10턴↓) | 중간 대화 (10-50턴) | **프로덕션 서비스** | **프로덕션 서비스** |
