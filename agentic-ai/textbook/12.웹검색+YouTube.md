## WHY?

LLM은 학습 데이터 컷오프 시점(예: 2024년 1월) 이후의 정보를 알 수 없으며, 실시간 데이터나 최신 콘텐츠에 접근할 수 없음

**실무 활용 사례**:

1. **최신 기술 문서**: "LangChain 0.3.0 새 기능" → LLM은 모르지만 웹 검색으로 공식 릴리즈 노트 확인
2. **실시간 이벤트**: "오늘 AWS re:Invent 발표 내용" → 웹 검색으로 최신 뉴스 조회
3. **시각적 학습**: "Kubernetes 배포 실습" → YouTube 튜토리얼로 단계별 과정 시청
4. **정보 검증**: LLM의 잘못된 답변(Hallucination) 방지 → 공식 문서 웹 검색으로 확인

## 빠른 시작 (Quick Start)

5분 안에 웹검색과 YouTube 검색을 시작하는 최소 예제.

### 설치

```bash
# 필수 패키지
pip install langchain-community langchain-openai duckduckgo-search youtube_search

# (선택) Tavily 사용 시
pip install langchain-tavily
```

### 웹 검색 (DuckDuckGo - 무료, API 키 불필요)

```python
from langchain_community.tools import DuckDuckGoSearchRun

search = DuckDuckGoSearchRun()
result = search.invoke("LangChain 최신 버전")
print(result)
```

### YouTube 검색 (무료, API 키 불필요)

```python
from langchain_community.tools import YouTubeSearchTool

youtube = YouTubeSearchTool()
result = youtube.run("LangChain tutorial,3")  # 3개 결과
print(result)
```

### 웹 + YouTube 통합 Agent (OpenAI API 키 필요)

```python
import os
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_openai import ChatOpenAI
from langchain_community.tools import DuckDuckGoSearchRun, YouTubeSearchTool
from langchain_core.prompts import ChatPromptTemplate

os.environ["OPENAI_API_KEY"] = "sk-..."

# 도구 설정
tools = [DuckDuckGoSearchRun(), YouTubeSearchTool()]
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 프롬프트
prompt = ChatPromptTemplate.from_messages([
    ("system", "웹과 YouTube를 검색하여 답변하는 어시스턴트입니다."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),  # Agent 중간 작업 공간 (scratchpad = 메모장)
    # - 변수명 "agent_scratchpad"는 LangChain 내부 규약, 변경 불가
    # - 도구 호출 요청, 도구 실행 결과가 이 위치에 자동 삽입됨
    # - Agent가 여러 번 도구를 호출할 때 이전 호출 기록 누적
    # - LLM이 이 기록을 보고 다음 행동(추가 도구 호출 or 최종 응답) 결정
])

# Agent 실행
agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

result = executor.invoke({"input": "RAG 구현 방법 알려줘"})
print(result["output"])
```

## 1. 개요

### 1.1 LangChain 웹검색 도구란?

LangChain 웹검색 도구는 Agent가 실시간 웹 정보를 검색하고 활용할 수 있게  
해주는 통합 인터페이스임.

**주요 특징**:
- 다양한 검색 프로바이더 지원 (Tavily, DuckDuckGo, Google 등)
- Agent와 쉽게 통합 가능
- 검색 결과를 LLM이 처리하기 좋은 형태로 반환

### 1.2 Tool vs Retriever 차이
툴을 선택적으로 호출 또는 강제적으로 호출  

| 구분 | Tool | Retriever |
|------|------|-----------|
| 툴 사용 결정 | LLM | 개발자 |
| 용도 | LLM이 필요하다고 판단할 때만 툴 실행 | 항상 검색 후 LLM 호출이 필요할 때 |
| 반환 형식 | 문자열 (검색 결과 요약) | Document 객체 리스트 |
| 예시 | `TavilySearchResults` | `TavilySearchAPIRetriever` |

**선택 기준**:
- LLM이 자율적으로 검색 여부 결정 → **Tool**
- 항상 검색 후 LLM에 컨텍스트 제공 → **Retriever**

### 1.3 YouTube 도구 개요

LangChain은 YouTube 콘텐츠를 활용하기 위한 두 가지 도구를 제공함.

| 도구 | 용도 | 반환 형식 | 사용 시점 |
|------|------|----------|----------|
| **YouTubeSearchTool** | 동영상 검색 | URL 리스트 (문자열) | 관련 영상 찾기 |
| **YoutubeLoader** | 자막/트랜스크립트 로드 | Document 객체 | 영상 내용 RAG |

**웹 검색 vs 영상 검색 선택 기준**:

| 상황 | 권장 소스 |
|------|----------|
| 최신 뉴스, 공식 문서, 기술 스펙 | 웹 검색 (Tavily) |
| 튜토리얼, 강의, 시각적 설명 | YouTube 검색 |
| 최신 정보 + 실습 가이드 모두 필요 | **멀티소스 (웹 + YouTube)** |

### 1.4 멀티소스 RAG 아키텍처 개요

여러가지 소스 데이터를 필요에 따라 조합하여 검색하는 **Agentic RAG** 구조:

```
┌─────────────────────────────────────────────────────────┐
│                     User Query                          │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                  Query Router                           │
│          "이 질문은 어떤 소스가 적합한가?"               │
└─────────────────────────────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
   ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
   │ Web Search  │ │YouTube Search│ │ Vector DB   │
   │  (Tavily)   │ │   + Loader  │ │  (문서)     │
   └─────────────┘ └─────────────┘ └─────────────┘
          │               │               │
          └───────────────┴───────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│              Result Synthesis (LLM)                     │
└─────────────────────────────────────────────────────────┘
```

## 2. 주요 프로바이더 비교

실무에서 가장 많이 사용되는 4개 프로바이더 비교.

| 프로바이더 | API 키 | 가격 | 특징 | 추천 용도 |
|-----------|--------|------|------|----------|
| **Tavily** | 필요 | $49/월~ | LLM 최적화 결과 반환 | AI Agent 표준 |
| **DuckDuckGo** | 불필요 | 무료 | 간단, 프라이버시 중시 | 프로토타이핑/학습 |
| **Google Serper** | 필요 | $50/2,500건 | Google 검색 결과 | Google 검색 필요시 |
| **SerpAPI** | 필요 | $50/월~ | 다양한 검색엔진 | 엔터프라이즈 |

### 2.1 Tavily

- **장점**: AI Agent용으로 설계됨, 깔끔한 결과, LangChain 공식 예제에서 표준 사용
- **단점**: 유료
- **패키지**: `langchain-tavily`

### 2.2 DuckDuckGo

- **장점**: 무료, API 키 불필요, 빠른 시작
- **단점**: 속도 느림, 결과 품질 중간
- **패키지**: `langchain-community`

### 2.3 Google Serper

- **장점**: Google 검색 제공, 저렴, 빠름
- **단점**: API 키 필요
- **패키지**: `langchain-community`

### 2.4 SerpAPI

- **장점**: Google/Bing/Yahoo 등 다양한 검색 엔진 지원, 안정적
- **단점**: 비용 높음
- **패키지**: `langchain-community`

### 2.5 YouTube Search Tool

YouTube에서 동영상을 검색하여 URL 목록을 반환하는 도구.

| 항목 | 내용 |
|------|------|
| **패키지** | `langchain-community`, `youtube_search` |
| **API 키** | 불필요 (웹 스크래핑 방식) |
| **가격** | 무료 |
| **반환** | YouTube URL 리스트 |
| **용도** | Agent가 동적으로 영상 검색 |

- **장점**: 무료, API 키 불필요, Agent Tool로 바로 사용
- **단점**: 웹 스크래핑 방식이라 YouTube 페이지 변경 시 불안정할 수 있음
- **주의**: Rate Limiting 없음 - 과도한 호출 시 IP 차단 가능

### 2.6 YouTube Data API v3

Google 공식 YouTube API로 동영상을 검색하는 방법. 날짜 필터링, 정렬 옵션 등 고급 기능 제공.

| 항목 | 내용 |
|------|------|
| **패키지** | `google-api-python-client` |
| **API 키** | 필요 (Google Cloud Console에서 발급) |
| **가격** | 무료 할당량: 10,000 units/일 (검색 1회 = 100 units, 약 100회/일) |
| **반환** | 영상 제목, 채널명, URL, 설명 등 상세 메타데이터 |
| **용도** | 날짜 필터링이 필요한 검색, 프로덕션 환경 |

- **장점**: 날짜 필터링(`publishedAfter`), 정렬 옵션, 안정적인 공식 API, 상세 메타데이터
- **단점**: API 키 필요, 일일 할당량 제한
- **vs YouTubeSearchTool**: YouTubeSearchTool은 무료/간편하지만 날짜 필터링 불가. API v3는 최근 N일 영상만 검색 가능

**설치**:
```bash
pip install google-api-python-client
```

**API 키 발급**:
1. [Google Cloud Console](https://console.cloud.google.com/) 접속
2. 프로젝트 생성 또는 선택
3. "APIs & Services" → "Library" → "YouTube Data API v3" 활성화
4. "APIs & Services" → "Credentials" → "CREATE CREDENTIALS" → "API key"
5. 발급된 API 키를 `.env` 파일에 저장

**기본 사용**:
```python
import os
from googleapiclient.discovery import build
from datetime import datetime, timedelta, timezone

# API 클라이언트 생성
api_key = os.environ.get("YOUTUBE_API_KEY")
youtube = build("youtube", "v3", developerKey=api_key)

# 검색 실행
request = youtube.search().list(
    q="LangChain tutorial",
    part="snippet",
    type="video",
    order="relevance",
    maxResults=5,
    relevanceLanguage="ko"  # 한국어 우선
)
response = request.execute()

# 결과 출력
for item in response.get("items", []):
    title = item["snippet"]["title"]
    channel = item["snippet"]["channelTitle"]
    video_id = item["id"]["videoId"]
    url = f"https://www.youtube.com/watch?v={video_id}"
    print(f"{title} ({channel})\n  {url}")
```

**날짜 필터링 (최근 N일)**:
```python
from datetime import datetime, timedelta, timezone

# 최근 365일 (1년) 필터
published_after = (
    datetime.now(timezone.utc) - timedelta(days=365)
).strftime("%Y-%m-%dT%H:%M:%SZ")

request = youtube.search().list(
    q="RAG tutorial",
    part="snippet",
    type="video",
    order="relevance",
    publishedAfter=published_after,  # 이 날짜 이후 영상만
    maxResults=5,
    relevanceLanguage="ko"
)
response = request.execute()
```

**주요 파라미터**:

| 파라미터 | 설명 |
|----------|------|
| `q` | 검색어 |
| `part` | 반환할 데이터 ("snippet"이 기본, "id"만 필요시 "id") |
| `type` | 검색 유형 ("video", "channel", "playlist") |
| `order` | 정렬 방식 ("relevance", "date", "viewCount", "rating") |
| `maxResults` | 반환 개수 (최대 50) |
| `publishedAfter` | 이 날짜 이후 영상만 (ISO 8601 형식) |
| `publishedBefore` | 이 날짜 이전 영상만 (ISO 8601 형식) |
| `relevanceLanguage` | 언어 우선순위 (ISO 639-1 코드, 예: "ko", "en") |
| `regionCode` | 지역 코드 (ISO 3166-1 alpha-2, 예: "KR", "US") |

**함수로 래핑 (실무 예제)**:
```python
import os
from googleapiclient.discovery import build
from datetime import datetime, timedelta, timezone
from dotenv import load_dotenv

load_dotenv()

def search_youtube(
    query: str,
    max_results: int = 5,
    days: int = 365,
    language: str = "ko"
) -> list[dict]:
    """YouTube Data API v3로 영상 검색
    
    Args:
        query: 검색어
        max_results: 반환할 영상 개수 (기본 5개)
        days: 최근 N일 이내 영상만 검색 (기본 365일)
        language: 언어 우선순위 (기본 한국어)
    
    Returns:
        영상 정보 리스트 [{"title": ..., "channel": ..., "url": ...}, ...]
    """
    api_key = os.environ.get("YOUTUBE_API_KEY")
    if not api_key:
        raise ValueError("YOUTUBE_API_KEY가 설정되지 않았습니다")
    
    youtube = build("youtube", "v3", developerKey=api_key)
    
    # 날짜 필터 계산
    published_after = (
        datetime.now(timezone.utc) - timedelta(days=days)
    ).strftime("%Y-%m-%dT%H:%M:%SZ")
    
    # 검색 요청
    request = youtube.search().list(
        q=query,
        part="snippet",
        type="video",
        order="relevance",
        publishedAfter=published_after,
        maxResults=max_results,
        relevanceLanguage=language
    )
    response = request.execute()
    
    # 결과 파싱
    results = []
    for item in response.get("items", []):
        results.append({
            "title": item["snippet"]["title"],
            "channel": item["snippet"]["channelTitle"],
            "url": f"https://www.youtube.com/watch?v={item['id']['videoId']}",
            "description": item["snippet"]["description"],
            "published_at": item["snippet"]["publishedAt"]
        })
    
    return results

# 사용 예시
videos = search_youtube("LangGraph 튜토리얼", max_results=3, days=180)
for v in videos:
    print(f"{v['title']} ({v['channel']})\n  {v['url']}")
```

> **YouTubeSearchTool vs YouTube Data API v3 선택 기준**:
> - **YouTubeSearchTool**: 빠른 프로토타이핑, 무료, API 키 불필요, 날짜 필터링 불필요 시
> - **YouTube Data API v3**: 프로덕션 환경, 날짜 필터링 필요, 상세 메타데이터 필요 시

**소스 링크 포함 결과 반환 (`results()` 메서드)**:

`run()` 메서드는 텍스트만 반환하지만, `results()` 메서드는 제목, 스니펫, **링크**를 포함한 상세 결과를 반환.

```python

    region="ko-kr",
    time="y",         # 최근 1년
    max_results=5,
)

# results() 메서드로 상세 결과 반환
results = wrapper.results("AI 트렌드")

for r in results:
    print(f"제목: {r['title']}")
    print(f"내용: {r['snippet']}")
    print(f"링크: {r['link']}")  # 소스 URL 포함
    print("---")
```

> **`run()` vs `results()` 차이**:
> - `run()`: 텍스트만 반환 (스니펫 연결)
> - `results()`: `[{"title": ..., "snippet": ..., "link": ...}, ...]` 형태로 반환
> 
> 출처 URL이 필요한 경우 `results()` 메서드 사용 권장.

> **Region Code**: `region`은 `언어-국가` 형식 사용.  
> 전체 목록: [DuckDuckGo Regions](https://duckduckgo.com/duckduckgo-help-pages/settings/params/)  
> 주요 코드: `ko-kr`(한국), `us-en`(미국), `jp-jp`(일본), `cn-zh`(중국), `uk-en`(영국)

`youtube_search` 패키지 직접 사용 시 `duration` 필드로 효율적 필터링 가능.
```python
from youtube_search import YoutubeSearch

# 검색 실행 (duration 포함된 결과 반환)
results = YoutubeSearch("LangChain tutorial", max_results=10).to_dict()

# 1시간 미만 영상만 필터링 (duration 형식: "MM:SS" 또는 "H:MM:SS")
```

분 단위로 세밀하게 필터링:
```python
from youtube_search import YoutubeSearch

def duration_to_seconds(duration: str) -> int:
    """duration 문자열을 초 단위로 변환"""
    parts = list(map(int, duration.split(":")))
    if len(parts) == 2:      # MM:SS
        return parts[0] * 60 + parts[1]
    elif len(parts) == 3:    # H:MM:SS
        return parts[0] * 3600 + parts[1] * 60 + parts[2]
    return 0

# 검색 및 필터링
results = YoutubeSearch("RAG tutorial", max_results=20).to_dict()
max_minutes = 20

filtered = [
    v for v in results 
    if duration_to_seconds(v["duration"]) <= max_minutes * 60
]

for v in filtered:
    print(f"{v['title']} ({v['duration']})")
```

### 3.6 YouTube Data API v3

Google 공식 YouTube API를 직접 사용하는 방법. 날짜 필터링, 정렬 옵션 등 고급 기능 제공.

**주요 파라미터**:

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| `q` | 필수 | 검색 쿼리 |
| `part` | 필수 | 반환할 정보. `snippet`(기본 정보), `id`, `statistics` 등 |

**실무용 함수 래핑**:
```python
import os
from googleapiclient.discovery import build
from datetime import datetime, timedelta, timezone
from dotenv import load_dotenv

load_dotenv()

def search_youtube(
    query: str,
    max_results: int = 5,
    days: int = 365,
    language: str = "ko"
) -> list[dict]:
    """YouTube Data API v3로 영상 검색
    
    Args:
        query: 검색어
        max_results: 반환할 영상 개수 (기본 5개)
        days: 최근 N일 이내 영상만 검색 (기본 365일)
        language: 언어 우선순위 (기본 한국어)
    
    Returns:
        영상 정보 리스트 [{"title": ..., "channel": ..., "url": ...}, ...]
    """
    api_key = os.environ.get("YOUTUBE_API_KEY")
    if not api_key:
        raise ValueError("YOUTUBE_API_KEY가 설정되지 않았습니다")
    
    youtube = build("youtube", "v3", developerKey=api_key)
    
    # 날짜 필터 계산
    published_after = (
        datetime.now(timezone.utc) - timedelta(days=days)
    ).strftime("%Y-%m-%dT%H:%M:%SZ")
    
    # 검색 요청
    request = youtube.search().list(
        q=query,
        part="snippet",
        type="video",
        order="relevance",
        publishedAfter=published_after,
        maxResults=max_results,
        relevanceLanguage=language
    )
    response = request.execute()
    
    # 결과 파싱
    results = []
    for item in response.get("items", []):
        results.append({
            "title": item["snippet"]["title"],
            "channel": item["snippet"]["channelTitle"],
            "url": f"https://www.youtube.com/watch?v={item['id']['videoId']}",
            "description": item["snippet"]["description"],
            "published_at": item["snippet"]["publishedAt"]
        })
    
    return results

# 사용 예시
videos = search_youtube("LangGraph 튜토리얼", max_results=3, days=180)
for v in videos:
    print(f"{v['title']} ({v['channel']})\n  {v['url']}")
```

### 3.7 YoutubeLoader

**주요 파라미터**:

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| `youtube_url` | 필수 | YouTube 영상 URL |
| `add_video_info` | False | `True` 시 제목, 설명, 조회수 등 메타데이터 포함 |
| `language` | `["en"]` | 자막 언어 우선순위 (예: `["ko", "en"]`) |
| `translation` | None | 자막 번역 언어 (예: `"ko"`) |
| `transcript_format` | `TEXT` | 자막 형식. `TEXT`(전체 텍스트), `CHUNKS`(타임스탬프 청크) |
| `chunk_size_seconds` | None | 청크 분할 시간 (초 단위, `CHUNKS` 모드에서만) |
| `continue_on_failure` | False | 오류 시 계속 진행 |

> **Language Code**: `language`와 `translation`은 [ISO 639-1 코드](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes) 사용.  
> 주요 코드: `ko`(한국어), `en`(영어), `ja`(일본어), `zh-Hans`(중국어 간체), `es`(스페인어), `fr`(프랑스어)

> **pytube 호환성 주의**: `add_video_info=True` 설정 시 내부적으로 `pytube` 라이브러리를 사용하여 영상 메타데이터(제목, 설명, 조회수 등)를 가져옴. YouTube API 변경으로 `pytube`가 정상 동작하지 않아 오류가 발생할 수 있음. 안정적인 동작을 위해 `add_video_info=False`를 권장함. 영상 메타데이터가 꼭 필요한 경우 별도의 YouTube Data API v3 사용을 고려.
  
**결과 구조**:

| 메서드 | 반환 타입 | 내용 |
|--------|----------|------|
| `YoutubeLoader.load()` | list[Document] | Document 객체 (page_content: 자막 텍스트, metadata: URL, 제목 등) |

```python
from langchain_community.document_loaders import YoutubeLoader

def load_video_if_short(url: str, max_minutes: int = 30):
    """지정된 길이 이하의 영상만 로드"""
    loader = YoutubeLoader.from_youtube_url(url, add_video_info=True)
    docs = loader.load()
    
    if not docs:
        return None
    
    # 영상 길이 확인 (초 단위)
    length_seconds = docs[0].metadata.get("length_seconds", 0)
    length_minutes = length_seconds / 60
    
    if length_minutes > max_minutes:
        print(f"영상 길이 {length_minutes:.1f}분 > {max_minutes}분, 스킵")
        return None
    
    return docs

# 사용 예시
docs = load_video_if_short("https://www.youtube.com/watch?v=VIDEO_ID", max_minutes=20)
```

### 4.4 YouTube → Document 파이프라인

YouTube 영상을 검색하고 콘텐츠를 RAG에 활용하는 파이프라인.

```
YouTubeSearchTool (URL 획득)
    ↓
YoutubeLoader (자막 추출)
    ↓
TextSplitter (청킹)
    ↓
Vector Store / LLM
```

**전체 파이프라인 예제**:
```python
from langchain_community.tools import YouTubeSearchTool
from langchain_community.document_loaders import YoutubeLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

# 1. YouTube 검색으로 URL 획득
search_tool = YouTubeSearchTool()
search_results = search_tool.run("LangChain RAG tutorial,3")

# 문자열을 리스트로 변환
import ast
video_urls = ast.literal_eval(search_results)

# 2. 각 영상에서 자막 로드
all_docs = []
for url in video_urls:
    try:
        full_url = f"https://www.youtube.com{url}" if url.startswith("/watch") else url
        loader = YoutubeLoader.from_youtube_url(
            full_url,
            add_video_info=True,
            language=["ko", "en"],
        )
        docs = loader.load()
        all_docs.extend(docs)
        print(f"✓ 로드 완료: {docs[0].metadata.get('title', url)}")
    except Exception as e:
        print(f"✗ 로드 실패: {url} - {e}")

# 3. 텍스트 분할
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
)
splits = text_splitter.split_documents(all_docs)

# 4. Vector Store에 저장
vectorstore = Chroma.from_documents(
    documents=splits,
    embedding=OpenAIEmbeddings(),
    collection_name="youtube_rag",
)

# 5. 검색 테스트
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
results = retriever.invoke("RAG 파이프라인 구성 방법")

for doc in results:
    print(f"출처: {doc.metadata.get('title', 'Unknown')}")
    print(f"내용: {doc.page_content[:200]}...")
    print("---")
```

### 4.5 Retriever 검색 옵션

벡터 스토어에서 검색기(Retriever)를 생성할 때 사용할 수 있는 옵션 정리.

**기본 사용법**:
```python
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 10, "fetch_k": 30, "lambda_mult": 0.5}
)
```

**search_type 옵션**:

| search_type | 설명 |
|-------------|------|
| `"similarity"` | 코사인 유사도 기반 검색 (기본값). 가장 유사한 k개 문서 반환. 빠르지만 중복/유사 문서가 많이 반환될 수 있음 |
| `"mmr"` | Maximal Marginal Relevance (최대 한계 관련성). 관련성 + 다양성을 동시에 고려. 여러 소스에서 골고루 결과를 가져올 때 적합. fetch_k개 후보 중 다양성 고려하여 k개 선택 |
| `"similarity_score_threshold"` | 유사도 점수 임계값 기반 검색. score_threshold 이상인 문서만 반환. 품질 보장이 필요할 때 사용 |

**search_kwargs 파라미터**:

| 파라미터 | search_type | 설명 |
|----------|-------------|------|
| `k` | 모두 | 최종 반환할 문서 수 (기본값: 4). 값이 클수록 더 많은 컨텍스트 제공, 토큰 비용 증가 |
| `fetch_k` | mmr | MMR 계산을 위해 먼저 가져올 후보 문서 수 (기본값: 20). fetch_k > k 이어야 함. 값이 클수록 다양성 ↑, 계산 비용 ↑ |
| `lambda_mult` | mmr | 관련성 vs 다양성 가중치 (0~1, 기본값: 0.5). 1.0=관련성만, 0.0=다양성만, 0.5=균형 |
| `score_threshold` | similarity_score_threshold | 최소 유사도 점수 (0~1). 이 값 미만의 문서는 반환하지 않음. 예: 0.7 → 70% 이상 유사한 문서만 반환 |

**사용 예시**:

```python
# 1. 기본 유사도 검색 (빠른 검색)
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 5}
)

# 2. MMR 검색 (다양성 고려 - 여러 영상/문서에서 골고루 검색)
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 10,          # 최종 10개 반환
        "fetch_k": 30,    # 30개 후보 중 선택
        "lambda_mult": 0.5  # 관련성/다양성 균형
    }
)

# 3. 임계값 기반 검색 (품질 보장)
retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={
        "k": 10,
        "score_threshold": 0.7  # 70% 이상 유사한 문서만
    }
)
```

> **YouTube RAG 권장 설정**: 여러 영상에서 골고루 검색 결과를 가져오려면 `search_type="mmr"`과 `lambda_mult=0.5` 조합을 권장.

## 5. Agent 통합

### 5.1 LangGraph 방식 (권장)

LangGraph는 LangChain의 최신 Agent 프레임워크.

**설치**:
```bash
pip install langgraph langchain-openai langchain-tavily
```

**기본 Agent 구현**:
```python
import os
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, END
from langgraph.prebuilt import ToolNode
from langchain_openai import ChatOpenAI
from langchain_tavily import TavilySearch

os.environ["OPENAI_API_KEY"] = "..."
os.environ["TAVILY_API_KEY"] = "..."

# 도구 정의
tools = [TavilySearch(max_results=3)]

# 모델 설정
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
model = model.bind_tools(tools)  # 모델에 도구 바인딩 (도구 호출 기능 활성화)

# 상태 정의 - 그래프 전체에서 공유되는 데이터 구조
class AgentState(TypedDict):
    messages: list  # 대화 기록 (사용자 입력, LLM 응답, 도구 결과 누적)

# 노드 함수 - 각 노드에서 실행될 로직 정의
def call_model(state: AgentState):
    """LLM 호출 노드: 현재 상태의 메시지를 보고 응답 생성"""
    response = model.invoke(state["messages"])  # LLM에 메시지 전달
    return {"messages": state["messages"] + [response]}  # 응답을 메시지에 추가

def should_continue(state: AgentState):
    """분기 판단 함수: 도구 호출 필요 여부 결정"""
    last_message = state["messages"][-1]  # 마지막 LLM 응답 확인
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"  # 도구 호출 요청 있음 → "tools" 노드로
    return END  # 도구 호출 없음 → 그래프 종료

# 그래프 구성
workflow = StateGraph(AgentState)        # 상태 스키마 기반 그래프 생성
workflow.add_node("agent", call_model)   # "agent" 노드: LLM 호출 담당
workflow.add_node("tools", ToolNode(tools))  # "tools" 노드: 도구 실행 담당

workflow.set_entry_point("agent")        # 시작점을 "agent" 노드로 지정
workflow.add_conditional_edges(          # 조건부 분기 설정
    "agent",                             # - 출발 노드
    should_continue,                     # - 분기 판단 함수
    {                                    # - 반환값 → 다음 노드 매핑
        "tools": "tools",                #   "tools" 반환 시 → "tools" 노드로 이동
        END: END                         #   END 반환 시 → 그래프 종료
    }
)
workflow.add_edge("tools", "agent")      # "tools" 완료 후 "agent"로 복귀 (루프)

# 컴파일 및 실행
app = workflow.compile()  # 그래프를 실행 가능한 앱으로 컴파일

result = app.invoke({     # 그래프 실행
    "messages": [         # - messages: 초기 상태 (사용자 입력)
        ("user", "LangChain 최신 버전이 뭐야?")  # (역할, 내용) 튜플 형식
    ]
})

print(result["messages"][-1].content)  # 최종 응답 (마지막 메시지) 출력
```

### 5.2 AgentExecutor 방식 (레거시)

기존 LangChain Agent 방식. 간단한 사용에 적합.

**기본 사용**:
```python
import os
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_openai import ChatOpenAI
from langchain_tavily import TavilySearch
from langchain_core.prompts import ChatPromptTemplate

os.environ["OPENAI_API_KEY"] = "..."
os.environ["TAVILY_API_KEY"] = "..."

# 도구 및 모델 설정
tools = [TavilySearch(max_results=3)]
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 프롬프트 정의
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),  # Agent 중간 작업 공간 (scratchpad = 메모장)
    # - 변수명 "agent_scratchpad"는 LangChain 내부 규약, 변경 불가
    # - 도구 호출 요청, 도구 실행 결과가 이 위치에 자동 삽입됨
    # - Agent가 여러 번 도구를 호출할 때 이전 호출 기록 누적
    # - LLM이 이 기록을 보고 다음 행동(추가 도구 호출 or 최종 응답) 결정
])

# Agent 생성
agent = create_tool_calling_agent(  # 도구 호출 가능한 Agent 생성
    llm,                            # - LLM: 추론 및 도구 선택 담당
    tools,                          # - tools: 사용 가능한 도구 목록
    prompt                          # - prompt: 시스템 프롬프트 및 입력 템플릿
)
executor = AgentExecutor(           # Agent 실행기 생성
    agent=agent,                    # - agent: 위에서 생성한 Agent
    tools=tools,                    # - tools: 실제 도구 실행용 (agent와 동일해야 함)
    verbose=True                    # - verbose: True면 실행 과정 로그 출력
)

# 실행
result = executor.invoke({"input": "오늘 주요 뉴스가 뭐야?"})
print(result["output"])
```

```python
        return "tools"  # 도구 호출 요청 있음 → "tools" 노드로
    return END  # 도구 호출 없음 → 그래프 종료

# 그래프 구성
workflow = StateGraph(AgentState)        # 상태 스키마 기반 그래프 생성
workflow.add_node("agent", call_model)   # "agent" 노드: LLM 호출 담당
workflow.add_node("tools", ToolNode(tools))  # "tools" 노드: 도구 실행 담당

workflow.set_entry_point("agent")        # 시작점을 "agent" 노드로 지정
workflow.add_conditional_edges(          # 조건부 분기 설정
    "agent",                             # - 출발 노드
    should_continue,                     # - 분기 판단 함수
    {                                    # - 반환값 → 다음 노드 매핑
        "tools": "tools",                #   "tools" 반환 시 → "tools" 노드로 이동
        END: END                         #   END 반환 시 → 그래프 종료
    }
)
workflow.add_edge("tools", "agent")      # "tools" 완료 후 "agent"로 복귀 (루프)

app = workflow.compile()  # 그래프를 실행 가능한 앱으로 컴파일

# 실행
result = app.invoke({     # 그래프 실행
    "messages": [         # - messages: 초기 상태
        ("system", "웹과 YouTube를 활용하여 정보를 찾아주는 어시스턴트입니다."),
        ("user", "RAG 구현 방법 알려줘. 문서랑 영상 둘 다 찾아줘.")
    ]
})

print(result["messages"][-1].content)  # 최종 응답 (마지막 메시지) 출력
```

### 5.4 멀티소스 RAG 패턴

실시간으로 웹과 YouTube를 함께 검색하여 RAG를 수행하는 패턴.

#### 5.4.1 Query Routing 패턴

쿼리를 분석하여 적절한 검색 소스를 선택하는 패턴.

**라우팅 스키마 정의**:
```python
from pydantic import BaseModel, Field
from typing import Literal

class RouteQuery(BaseModel):
    """쿼리를 어떤 소스로 라우팅할지 결정"""
    sources: list[Literal["web", "youtube", "vectorstore"]] = Field(
        description="검색할 소스 목록"
    )
    reasoning: str = Field(
        description="소스 선택 이유"
    )

class SubQuery(BaseModel):
    """각 소스에 최적화된 서브쿼리"""
    source: Literal["web", "youtube", "vectorstore"]
    query: str = Field(description="해당 소스에 최적화된 검색어")
```

**라우터 함수 구현**:
```python
from langchain_openai import ChatOpenAI

def create_query_router(llm: ChatOpenAI):
    """쿼리 라우터 생성"""

    structured_llm = llm.with_structured_output(RouteQuery)

    def route(query: str) -> RouteQuery:
        return structured_llm.invoke([
            {"role": "system", "content": """
사용자 쿼리를 분석하여 검색할 소스를 결정하세요.

소스별 특징:
- web: 공식 문서, 기술 블로그, 최신 뉴스, API 레퍼런스
- youtube: 튜토리얼, 강의, 데모, 시각적 설명, 실습 가이드
- vectorstore: 내부 문서, 사전 인덱싱된 자료

선택 기준:
- 최신 정보가 필요하면: web, youtube
- 사용법/튜토리얼 필요하면: youtube
- 공식 스펙/문서 필요하면: web
- 여러 유형의 정보가 필요하면 복수 선택

예시:
- "LangChain 최신 버전" → ["web"]
- "LangGraph 사용법 튜토리얼" → ["youtube"]
- "RAG 구현 방법 전체" → ["web", "youtube"]
"""},
            {"role": "user", "content": query}
        ])

    return route
```

#### 5.4.2 병렬 검색 패턴

LangGraph의 `Send` API를 사용하여 여러 소스를 동시에 검색.

```python
import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send
from langchain_openai import ChatOpenAI
from langchain_tavily import TavilySearch
from langchain_community.tools import YouTubeSearchTool

# 상태 정의
class SearchState(TypedDict):
    query: str
    routes: list[str]
    results: Annotated[list[dict], operator.add]  # 결과 누적
    final_answer: str

# 검색 함수들
def search_web(state: dict) -> dict:
    """웹 검색"""
    tool = TavilySearch(max_results=5)
    result = tool.invoke(state["query"])
    return {"results": [{"source": "web", "content": result}]}

def search_youtube(state: dict) -> dict:
    """YouTube 검색"""
    tool = YouTubeSearchTool()
    result = tool.run(f"{state['query']},5")
    return {"results": [{"source": "youtube", "content": result}]}

# 라우팅 함수
def route_to_sources(state: SearchState) -> list[Send]:
    """라우팅 결과에 따라 병렬로 검색 실행"""
    sends = []
    for route in state["routes"]:
        if route == "web":
            sends.append(Send("search_web", {"query": state["query"]}))
        elif route == "youtube":
            sends.append(Send("search_youtube", {"query": state["query"]}))
    return sends

# 결과 통합
def synthesize(state: SearchState) -> dict:
    """검색 결과 통합"""
    llm = ChatOpenAI(model="gpt-4o-mini")

    formatted = "\n\n".join([
        f"[{r['source'].upper()}]\n{r['content']}"
        for r in state["results"]
    ])

    response = llm.invoke([
        {"role": "system", "content": f"""
다음 검색 결과를 바탕으로 질문에 답하세요: "{state['query']}"
- 웹과 영상 결과를 적절히 조합
- YouTube URL이 있으면 추천 영상으로 포함
- 출처 명시
"""},
        {"role": "user", "content": formatted}
    ])

    return {"final_answer": response.content}

# 그래프 구성
workflow = StateGraph(SearchState)
workflow.add_node("search_web", search_web)
workflow.add_node("search_youtube", search_youtube)
workflow.add_node("synthesize", synthesize)

workflow.add_conditional_edges(START, route_to_sources, ["search_web", "search_youtube"])
workflow.add_edge("search_web", "synthesize")
workflow.add_edge("search_youtube", "synthesize")
workflow.add_edge("synthesize", END)

app = workflow.compile()
```

#### 5.4.3 검색 → 상세 RAG 연계

YouTube 검색 결과에서 자막을 로드하여 상세 RAG 수행.

```python
from langchain_community.tools import YouTubeSearchTool
from langchain_community.document_loaders import YoutubeLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

def create_youtube_rag_chain(query: str, max_videos: int = 3):
    """YouTube 검색 → 자막 로드 → RAG 체인 생성"""

    # 1. YouTube 검색
    search_tool = YouTubeSearchTool()
    search_results = search_tool.run(f"{query},{max_videos}")

    import ast
    try:
        video_urls = ast.literal_eval(search_results)
    except:
        video_urls = []

    # 2. 자막 로드
    all_docs = []
    for url in video_urls:
        try:
            full_url = f"https://www.youtube.com{url}" if url.startswith("/watch") else url
            loader = YoutubeLoader.from_youtube_url(
                full_url,
                add_video_info=True,
                language=["ko", "en"],
            )
            docs = loader.load()
            all_docs.extend(docs)
        except Exception as e:
            print(f"로드 실패: {url} - {e}")

    if not all_docs:
        return None, "관련 YouTube 영상을 찾지 못했습니다."

    # 3. 텍스트 분할 및 인덱싱
    splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
    splits = splitter.split_documents(all_docs)

    vectorstore = Chroma.from_documents(
        documents=splits,
        embedding=OpenAIEmbeddings(),
    )
    retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

    # 4. RAG 체인 생성
    prompt = ChatPromptTemplate.from_template("""
다음 YouTube 영상의 내용을 바탕으로 질문에 답하세요.

컨텍스트:
{context}

질문: {question}

답변 시 참고한 영상 제목을 함께 언급해주세요.
""")

    llm = ChatOpenAI(model="gpt-4o-mini")

    def format_docs(docs):
        return "\n\n".join([
            f"[{doc.metadata.get('title', 'Unknown')}]\n{doc.page_content}"
            for doc in docs
        ])

    chain = (
        {"context": retriever | format_docs, "question": RunnablePassthrough()}
        | prompt
        | llm
        | StrOutputParser()
    )

    # 로드된 영상 목록
    video_titles = list(set([
        doc.metadata.get('title', 'Unknown') for doc in all_docs
    ]))

    return chain, video_titles

# 사용 예시
chain, videos = create_youtube_rag_chain("LangGraph 에이전트 만들기")
if chain:
    print(f"참고 영상: {videos}")
    answer = chain.invoke("LangGraph에서 상태 관리는 어떻게 하나요?")
    print(answer)
```

#### 5.4.4 실전 예제: 기술 학습 어시스턴트

웹 문서와 YouTube 튜토리얼을 함께 활용하는 완전한 멀티소스 RAG 시스템.

```python
import os
from typing import Annotated, TypedDict, Literal
import operator
from pydantic import BaseModel, Field
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send
from langchain_openai import ChatOpenAI
from langchain_tavily import TavilySearch
from langchain_community.tools import YouTubeSearchTool

os.environ["OPENAI_API_KEY"] = "..."
os.environ["TAVILY_API_KEY"] = "..."

# === 스키마 정의 ===
class RouteDecision(BaseModel):
    sources: list[Literal["web", "youtube"]] = Field(
        description="검색할 소스 목록"
    )

class SearchResult(TypedDict):
    source: str
    content: str

class AssistantState(TypedDict):
    query: str
    routes: list[str]
    results: Annotated[list[SearchResult], operator.add]
    answer: str

# === 노드 함수들 ===
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

def classify_query(state: AssistantState) -> dict:
    """쿼리 분석 및 소스 선택"""
    router = llm.with_structured_output(RouteDecision)

    decision = router.invoke([
        {"role": "system", "content": """
기술 관련 쿼리를 분석하여 검색할 소스를 결정하세요.

- web: 공식 문서, API 레퍼런스, 기술 블로그, 최신 뉴스
- youtube: 튜토리얼, 강의, 데모, 실습 가이드

대부분의 학습 관련 질문은 둘 다 유용합니다.
"""},
        {"role": "user", "content": state["query"]}
    ])

    return {"routes": decision.sources}

def route_search(state: AssistantState) -> list[Send]:
    """선택된 소스로 병렬 검색"""
    sends = []
    for route in state["routes"]:
        sends.append(Send(f"search_{route}", {"query": state["query"]}))
    return sends

def search_web(state: dict) -> dict:
    tool = TavilySearch(max_results=5)
    result = tool.invoke(state["query"])
    return {"results": [{"source": "web", "content": str(result)}]}

def search_youtube(state: dict) -> dict:
    tool = YouTubeSearchTool()
    result = tool.run(f"{state['query']},5")
    return {"results": [{"source": "youtube", "content": result}]}

def generate_answer(state: AssistantState) -> dict:
    """멀티소스 결과 종합 답변"""

    # 결과 포맷팅
    web_results = [r for r in state["results"] if r["source"] == "web"]
    youtube_results = [r for r in state["results"] if r["source"] == "youtube"]

    context = ""
    if web_results:
        context += f"## 웹 검색 결과\n{web_results[0]['content']}\n\n"
    if youtube_results:
        context += f"## YouTube 검색 결과\n{youtube_results[0]['content']}\n\n"

    response = llm.invoke([
        {"role": "system", "content": """
당신은 기술 학습 어시스턴트입니다.
웹 문서와 YouTube 영상 검색 결과를 바탕으로 종합적인 답변을 제공하세요.

답변 형식:
1. 핵심 개념 설명 (웹 문서 기반)
2. 추천 학습 영상 (YouTube 링크 포함)
3. 추가 학습 자료 (웹 링크 포함)
"""},
        {"role": "user", "content": f"질문: {state['query']}\n\n검색 결과:\n{context}"}
    ])

    return {"answer": response.content}

# === 그래프 구성 ===
workflow = StateGraph(AssistantState)

# 노드 추가
workflow.add_node("classify", classify_query)
workflow.add_node("search_web", search_web)
workflow.add_node("search_youtube", search_youtube)
workflow.add_node("generate", generate_answer)

# 엣지 연결
workflow.add_edge(START, "classify")
workflow.add_conditional_edges("classify", route_search, ["search_web", "search_youtube"])
workflow.add_edge("search_web", "generate")
workflow.add_edge("search_youtube", "generate")
workflow.add_edge("generate", END)

# 컴파일
assistant = workflow.compile()

# === 실행 ===
def ask(question: str) -> str:
    result = assistant.invoke({"query": question})
    return result["answer"]

# 테스트
if __name__ == "__main__":
    questions = [
        "LangGraph로 멀티 에이전트 시스템 만드는 방법",
        "RAG 파이프라인 최적화 방법",
        "Vector Database 선택 가이드",
    ]

    for q in questions:
        print(f"\n{'='*60}")
        print(f"Q: {q}")
        print(f"{'='*60}")
        print(ask(q))
```

### 6.1 캐싱 - 성능 향상

동일 쿼리 반복 검색 방지로 비용 절감 및 속도 향상.

**메모리 캐싱** 
```python
from functools import lru_cache
from langchain_tavily import TavilySearch

search = TavilySearch()

@lru_cache(maxsize=100)
def cached_search(query: str) -> str:
    """검색 결과 캐싱"""
    return search.invoke(query)

# 사용
result1 = cached_search("LangChain 튜토리얼")  # API 호출
result2 = cached_search("LangChain 튜토리얼")  # 캐시에서 반환
```

**Redis 캐싱 (프로덕션)**:
```python
import redis
import json
import hashlib

redis_client = redis.Redis(host="localhost", port=6379, db=0)

def cached_search_redis(query: str, ttl: int = 3600) -> str:
    """Redis 기반 캐싱 (TTL 1시간)"""
    cache_key = f"search:{hashlib.md5(query.encode()).hexdigest()}"
    
    # 캐시 확인
    cached = redis_client.get(cache_key)
    if cached:
        return cached.decode()
    
    # 검색 실행
    result = search.invoke(query)
    
    # 캐시 저장
    redis_client.setex(cache_key, ttl, result)
    
    return result
```

> **주의**: 위 방식들은 쿼리 문자열이 정확히 일치해야 캐시 히트.  
> "LangChain 튜토리얼" vs "langchain tutorial" → 캐시 미스.  
> 의미적으로 유사한 쿼리도 캐시 활용하려면 임베딩 기반 유사도 캐싱 사용.

**임베딩 기반 유사도 캐싱**:

의미적으로 유사한 쿼리는 동일 캐시 결과 반환. 쿼리 표현이 달라도 캐시 히트 가능.

#### (1) 메모리 기반 (개발/테스트용)

```python
import numpy as np
from langchain_openai import OpenAIEmbeddings
from langchain_tavily import TavilySearch

class SemanticCache:
    """임베딩 기반 유사도 캐싱"""
    
    def __init__(self, similarity_threshold: float = 0.92):
        self.embeddings = OpenAIEmbeddings()
        self.search = TavilySearch(max_results=5)
        self.cache: list[dict] = []  # {"query": str, "embedding": np.array, "result": str}
        self.threshold = similarity_threshold  # 유사도 임계값 (0.92 = 92% 이상 유사하면 캐시 히트)
    
    def _cosine_similarity(self, a: np.ndarray, b: np.ndarray) -> float:
        """코사인 유사도 계산"""
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
    
    def _find_similar(self, query_embedding: np.ndarray) -> dict | None:
        """캐시에서 유사한 쿼리 검색"""
        for item in self.cache:
            similarity = self._cosine_similarity(query_embedding, item["embedding"])
            if similarity >= self.threshold:
                return item
        return None
    
    def search_with_cache(self, query: str) -> str:
        """유사도 기반 캐시 검색"""
        # 1. 쿼리 임베딩 생성
        query_embedding = np.array(self.embeddings.embed_query(query))
        
        # 2. 캐시에서 유사한 쿼리 검색
        cached = self._find_similar(query_embedding)
        if cached:
            print(f"캐시 히트: '{query}' ≈ '{cached['query']}'")
            return cached["result"]
        
        # 3. 캐시 미스 → 실제 검색 실행
        print(f"캐시 미스: '{query}' 검색 실행")
        result = self.search.invoke(query)
        
        # 4. 결과 캐시에 저장
        self.cache.append({
            "query": query,
            "embedding": query_embedding,
            "result": result
        })
        
        return result

# 사용 예시
cache = SemanticCache(similarity_threshold=0.90)

# 첫 번째 검색 → 캐시 미스, API 호출
result1 = cache.search_with_cache("LangChain 튜토리얼")

# 유사한 쿼리 → 캐시 히트 (API 호출 없음)
result2 = cache.search_with_cache("langchain tutorial")      # 캐시 히트
result3 = cache.search_with_cache("LangChain 사용법 강의")   # 캐시 히트
result4 = cache.search_with_cache("랭체인 튜토리얼")         # 캐시 히트
```

> **similarity_threshold 조정**:  
> - 높음 (0.95+): 거의 동일한 쿼리만 캐시 히트, 정확도 ↑  
> - 낮음 (0.85-): 넓은 범위 캐시 히트, 잘못된 결과 반환 위험 ↑  
> - 권장: 0.90 ~ 0.92

> **다국어 지원**: OpenAI Embeddings 등 다국어 임베딩 모델 사용 시
> "LangChain tutorial" ≈ "LangChain 튜토리얼" ≈ "랭체인 사용법"처럼
> 언어가 달라도 의미적으로 유사하면 캐시 히트 가능. 글로벌 서비스에서 캐시 히트율 ↑

#### (2) Redis 기반 (프로덕션 권장)

Redis Stack의 벡터 검색 기능을 활용한 확장 가능한 임베딩 캐싱.

**설치**:

**구현**:
```python
import numpy as np
from redis import Redis
from redis.commands.search.field import VectorField, TextField
from redis.commands.search.indexDefinition import IndexDefinition, IndexType
from redis.commands.search.query import Query
from langchain_openai import OpenAIEmbeddings
from langchain_tavily import TavilySearch

class RedisSemanticCache:
    """Redis 기반 임베딩 유사도 캐싱"""

    def __init__(
        self,
        redis_url: str = "redis://localhost:6379",
        similarity_threshold: float = 0.92,
        vector_dim: int = 1536  # OpenAI embedding 차원
    ):
        self.redis_client = Redis.from_url(redis_url, decode_responses=False)
        self.embeddings = OpenAIEmbeddings()
        self.search = TavilySearch(max_results=5)
        self.threshold = similarity_threshold
        self.index_name = "query_cache_idx"

        # 벡터 인덱스 생성
        self._create_index(vector_dim)

    def _create_index(self, vector_dim: int):
        """Redis 벡터 인덱스 생성"""
        try:
            self.redis_client.ft(self.index_name).dropindex(delete_documents=False)
        except:
            pass

        schema = (
            TextField("query"),
            TextField("result"),
            VectorField(
                "embedding",
                "HNSW",  # 빠른 근사 검색
                {
                    "TYPE": "FLOAT32",
                    "DIM": vector_dim,
                    "DISTANCE_METRIC": "COSINE",
                    "M": 16,
                    "EF_CONSTRUCTION": 200
                }
            )
        )

        self.redis_client.ft(self.index_name).create_index(
            fields=schema,
            definition=IndexDefinition(prefix=["cache:"], index_type=IndexType.HASH)
        )

    def search_with_cache(self, query: str) -> str:
        """유사도 기반 캐시 검색"""
        # 1. 쿼리 임베딩 생성
        query_embedding = self.embeddings.embed_query(query)
        embedding_bytes = np.array(query_embedding, dtype=np.float32).tobytes()

        # 2. Redis 벡터 검색
        knn_query = (
            Query(f"*=>[KNN 1 @embedding $vec AS score]")
            .return_fields("query", "result", "score")
            .sort_by("score")
            .dialect(2)
        )

        result = self.redis_client.ft(self.index_name).search(
            knn_query,
            query_params={"vec": embedding_bytes}
        )

        # 3. 임계값 확인
        if result.docs:
            similarity = 1 - float(result.docs[0].score)  # 코사인 거리 → 유사도
            if similarity >= self.threshold:
                cached_query = result.docs[0].query
                cached_result = result.docs[0].result
                print(f"캐시 히트: '{query}' ≈ '{cached_query}' (유사도: {similarity:.2f})")
                return cached_result

        # 4. 캐시 미스 → 실제 검색
        print(f"캐시 미스: '{query}' 검색 실행")
        search_result = self.search.invoke(query)

        # 5. Redis에 저장
        cache_key = f"cache:{hash(query)}"
        self.redis_client.hset(
            cache_key,
            mapping={
                "query": query,
                "result": search_result,
                "embedding": embedding_bytes
            }
        )

        return search_result

# 사용 예시
cache = RedisSemanticCache(similarity_threshold=0.90)

result1 = cache.search_with_cache("LangChain 튜토리얼")      # 캐시 미스
result2 = cache.search_with_cache("langchain tutorial")      # 캐시 히트
result3 = cache.search_with_cache("랭체인 사용법")           # 캐시 히트
```

**메모리 vs Redis 비교**:

| 구분 | 메모리 기반 | Redis 기반 |
|------|------------|-----------|
| 영속성 | ❌ 프로세스 종료 시 소멸 | ✅ 영구 보관 |
| 공유 | ❌ 단일 프로세스 | ✅ 여러 인스턴스 공유 |
| 확장성 | ❌ 메모리 제한 | ✅ 수백만 개 캐시 |
| 검색 속도 | O(n) 선형 | O(log n) HNSW |
| 분산 환경 | ❌ 불가 | ✅ 가능 |
| 복잡도 | 간단 | 중간 |
| 권장 용도 | 개발/테스트 | 프로덕션 |

> **HNSW 알고리즘**: Hierarchical Navigable Small World
> - 대규모 벡터 검색에 최적화된 근사 최근접 이웃(ANN) 알고리즘
> - FLAT(정확하지만 느림) 대신 HNSW(빠르고 근사치) 사용 권장

### 6.2 Resilience 패턴 - 안정성 향상

API 오류, 네트워크 장애, Rate Limit 등 예외 상황에 대응하는 패턴.

#### 6.2.1 재시도 (Retry)

일시적 오류 발생 시 자동으로 재시도하여 성공률 향상.

```python
from tenacity import retry, stop_after_attempt, wait_exponential
from langchain_tavily import TavilySearch

search = TavilySearch()

@retry(
    stop=stop_after_attempt(5),  # 최대 5번 시도 후 중단
    wait=wait_exponential(       # 지수 백오프 대기
        multiplier=2,            # - 배수 (대기시간 = multiplier * 2^(시도횟수-1))
        min=2,                   # - 최소 대기 시간 (초)
        max=10                   # - 최대 대기 시간 (초), 초과 시 이 값으로 제한
    ),
)
def search_with_retry(query: str) -> str:
    """재시도 로직 포함 검색"""
    return search.invoke(query)

# 사용
try:
    result = search_with_retry("검색어")
except Exception as e:
    result = f"검색 실패: {e}"  # 5번 모두 실패 시 예외 발생
```

**시도별 대기 시간** (`multiplier=2`, `max=10`):

| 시도 | 계산식 | 대기 시간 |
|------|--------|----------|
| 1차 실패 후 | `2 * 2^(1-1)` = 2 | 2초 |
| 2차 실패 후 | `2 * 2^(2-1)` = 4 | 4초 |
| 3차 실패 후 | `2 * 2^(3-1)` = 8 | 8초 |
| 4차 실패 후 | `2 * 2^(4-1)` = 16 | 10초 (max 제한) |
| 5차 실패 후 | - | 종료 |

**tenacity 주요 파라미터**:

| 카테고리 | 함수 | 설명 |
|----------|------|------|
| **Stop (중단)** | `stop_after_attempt(n)` | n번 시도 후 중단 |
| | `stop_after_delay(seconds)` | 지정 시간 경과 후 중단 |
| | `stop_any(stop1, stop2)` | 조건 중 하나라도 만족 시 중단 |
| **Wait (대기)** | `wait_exponential(multiplier, min, max)` | 지수 백오프 |
| | `wait_fixed(seconds)` | 고정 대기 시간 |
| | `wait_random(min, max)` | 랜덤 대기 시간 |
| | `wait_random_exponential(multiplier, max)` | 지수 백오프 + Jitter (권장) |
| **Retry 조건** | `retry_if_exception_type(ExceptionClass)` | 특정 예외 발생 시만 재시도 |
| | `retry_if_result(predicate)` | 반환값 조건 만족 시 재시도 |
| | `retry_any(retry1, retry2)` | 조건 중 하나라도 만족 시 재시도 |
| **Callback** | `before_sleep_log(logger, level)` | 대기 전 로그 출력 |
| | `after_log(logger, level)` | 시도 후 로그 출력 |
| **기타** | `reraise=True` | 최종 실패 시 원본 예외 발생 |

> **`wait_random_exponential` 권장 이유**:  
> 여러 클라이언트가 동시에 재시도하면 서버에 부하가 집중됨 (Thundering Herd 문제).  
> 이 함수는 대기 시간에 랜덤 요소(Jitter)를 추가하여 요청을 분산시킴. Rate Limit 대응에 권장.

#### 6.2.2 폴백 (Fallback)

주 검색 도구 실패 시 대체 도구로 자동 전환.

```python
from langchain_tavily import TavilySearch
from langchain_community.tools import DuckDuckGoSearchRun

# 주/보조 검색 도구
primary_search = TavilySearch(max_results=5)
fallback_search = DuckDuckGoSearchRun()

def search_with_fallback(query: str) -> str:
    """폴백 포함 검색"""
    try:
        # 주 검색 도구 시도
        return primary_search.invoke(query)
    except Exception as e:
        print(f"Primary search failed: {e}, trying fallback...")
        try:
            # 보조 검색 도구 시도
            return fallback_search.invoke(query)
        except Exception as e2:
            return f"All search methods failed: {e2}"

# 사용
result = search_with_fallback("AI 트렌드 2024")
```

#### 6.2.3 Rate Limiting

API 호출 빈도 제한으로 과금 방지 및 Rate Limit 오류 예방.

```python
import time
from functools import wraps

def rate_limit(calls_per_minute: int = 10):
    """분당 호출 수 제한 데코레이터"""
    min_interval = 60.0 / calls_per_minute
    last_called = [0.0]
    
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            elapsed = time.time() - last_called[0]
            wait_time = min_interval - elapsed
            if wait_time > 0:
                time.sleep(wait_time)
            last_called[0] = time.time()
            return func(*args, **kwargs)
        return wrapper
    return decorator

@rate_limit(calls_per_minute=10)
def rate_limited_search(query: str) -> str:
    return search.invoke(query)
```

#### 6.2.4 Circuit Breaker

연속 실패 시 일정 시간 요청을 차단하여 시스템 보호. 장애 전파 방지.

```
┌─────────────────────────────────────────────────────────┐
│                  Circuit Breaker 상태                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   CLOSED ──(실패 임계값 초과)──▶ OPEN                   │
│     ▲                              │                    │
│     │                         (대기 시간 경과)          │
│     │                              ▼                    │
│     └────(성공)──── HALF-OPEN ◀───┘                    │
│                        │                                │
│                   (실패 시 다시 OPEN)                   │
│                                                         │
└─────────────────────────────────────────────────────────┘

- CLOSED: 정상 상태, 요청 통과
- OPEN: 차단 상태, 요청 즉시 실패 (빠른 실패)
- HALF-OPEN: 테스트 상태, 일부 요청만 통과
```

**pybreaker 사용**:
```bash
pip install pybreaker
```

```python
import pybreaker
from langchain_tavily import TavilySearch

# Circuit Breaker 설정
breaker = pybreaker.CircuitBreaker(
    fail_max=5,           # 5번 연속 실패 시 OPEN
    reset_timeout=30,     # 30초 후 HALF-OPEN으로 전환
)

search = TavilySearch(max_results=5)

@breaker
def search_with_breaker(query: str) -> str:
    """Circuit Breaker가 적용된 검색"""
    return search.invoke(query)

# 사용
try:
    result = search_with_breaker("AI 트렌드")
    print(result)
except pybreaker.CircuitBreakerError:
    # Circuit이 OPEN 상태 - 빠른 실패
    print("서비스 일시 중단 중, 잠시 후 재시도하세요")
```

**Retry + Circuit Breaker 조합 (권장)**:
```python
import pybreaker
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type
from langchain_tavily import TavilySearch

# Circuit Breaker
breaker = pybreaker.CircuitBreaker(fail_max=5, reset_timeout=30)

# Retry + Circuit Breaker 조합
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=1, max=10),
    retry=retry_if_exception_type((TimeoutError, ConnectionError)),
    reraise=True,
)
@breaker
def resilient_search(query: str) -> str:
    """Retry + Circuit Breaker가 적용된 검색
    
    동작 순서:
    1. Retry 데코레이터가 먼저 적용
    2. 각 시도마다 Circuit Breaker 통과
    3. Circuit OPEN 시 즉시 실패 (Retry 없이)
    """
    search = TavilySearch(max_results=5)
    return search.invoke(query)

# 사용
try:
    result = resilient_search("검색어")
except pybreaker.CircuitBreakerError:
    result = "서비스 일시 중단"
except Exception as e:
    result = f"최종 실패: {e}"
```

> **Retry vs Circuit Breaker 차이**:
> - **Retry**: 실패 시 재시도 (일시적 오류 대응)
> - **Circuit Breaker**: 연속 실패 시 차단 (시스템 보호)
> - **조합 사용**: Retry로 일시적 오류 복구, 연속 실패 시 Circuit Breaker가 차단

**YouTube 검색 호출 간격 제한 (IP 차단 방지)**:

YouTubeSearchTool은 웹 스크래핑 방식이라 과도한 호출 시 IP 차단될 수 있음. 호출 간격을 제한하여 방지.

```python
import time
from langchain_community.tools import YouTubeSearchTool

class RateLimitedYouTubeSearch:
    """호출 간격 제한이 적용된 YouTube 검색"""
    
    def __init__(self, min_interval: float = 2.0):
        self.tool = YouTubeSearchTool()
        self.min_interval = min_interval  # 최소 호출 간격 (초)
        self.last_call = 0
    
    def run(self, query: str) -> str:
        # 이전 호출로부터 경과 시간 계산
        elapsed = time.time() - self.last_call
        # 최소 간격보다 짧으면 대기
        if elapsed < self.min_interval:
            time.sleep(self.min_interval - elapsed)
        
        self.last_call = time.time()
        return self.tool.run(query)

# 사용 예시
search = RateLimitedYouTubeSearch(min_interval=2.0)  # 최소 2초 간격
result1 = search.run("LangChain tutorial")  # 즉시 실행
result2 = search.run("RAG tutorial")        # 2초 대기 후 실행
```

```
  - (중요) DuckDuckGo는 wrapper.results() 메서드를 사용하여 소스 링크 포함
```
```
  - (중요) web_query 생성 시 연도/시간 표현 제외 (DuckDuckGo time 필터가 자동 적용되므로)
  - (중요) YouTube 검색은 YouTube Data API v3 사용
  - (중요) YouTube 검색 시 최근 1년 필터 적용
  - (중요) youtube_query 생성 시 쉼표 없이 짧은 키워드 사용
```
