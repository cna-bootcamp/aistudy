## 2. 개요

### 2.1 VLM (Vision Language Model)

이미지와 텍스트를 함께 이해하고 처리하는 멀티모달 AI 모델.   
이미지를 입력받아 자연어로 설명하거나, 이미지에 대한 질문에 답변하는 등 다양한 시각-언어 태스크 수행 가능.

### 2.2 주요 활용 사례

| 분야 | 설명 |
|------|------|
| **이미지 캡셔닝** | 이미지 내용을 자연어로 설명 |
| **Visual QA** | 이미지에 대한 질문에 답변 |
| **문서/OCR 분석** | 문서, 차트, 표 등의 텍스트 추출 및 이해 |
| **이미지 검색** | 텍스트로 이미지 검색, 이미지로 유사 이미지 검색 |
| **접근성 향상** | 시각 장애인을 위한 이미지 설명 |
| **의료 영상 분석** | X-ray, CT 등 의료 이미지 판독 보조 |
| **품질 검사** | 제조업 제품 결함 탐지 |
| **자율주행** | 도로 상황 인식 및 판단 |

### 2.3 VLM 기술의 발전

| 세대 | 기술 | 특징 |
|:----:|------|------|
| 1세대 | CNN + RNN | 이미지 특징 추출 후 순차적 텍스트 생성 |
| 2세대 | Vision Transformer | Attention 기반 이미지 이해 |
| 3세대 | CLIP/ALIGN | 이미지-텍스트 대조 학습 |
| 4세대 | LLaVA/Qwen-VL | LLM과 Vision Encoder 통합, 범용 멀티모달 |

## 3. 모델 정보

### 3.1 Cloud API 기반 VLM

클라우드 서비스에서 제공하는 Vision API를 호출하여 이미지 분석. 설치 불필요, 즉시 사용 가능.

#### 3.1.1 Google Gemini Vision

Google에서 제공하는 멀티모달 AI 모델. 이미지, 텍스트, 오디오, 비디오 등 다양한 입력 처리 가능.

**특징**
- 간단한 API 호출로 이미지 분석
- 다국어 지원 (한국어 포함)
- 긴 컨텍스트 지원 (1M+ 토큰)
- GPU 불필요 (클라우드 처리)

**지원 이미지 형식**

| 포맷 | 확장자 | 비고 |
|------|--------|------|
| JPEG | .jpg, .jpeg | 가장 일반적 |
| PNG | .png | 투명 배경 지원 |
| WebP | .webp | 웹 최적화 포맷 |
| GIF | .gif | 정적 프레임만 처리 |
| HEIC | .heic | iOS 기본 포맷 |

**핵심 코드**

```python
from PIL import Image
from google import genai
from google.genai import types

client = genai.Client(api_key=api_key)

# 이미지 로드
image = Image.open("image.jpg")

# 생성 설정
generation_config = types.GenerateContentConfig(
    temperature=0.7,
    max_output_tokens=2048,
)

# 이미지 분석 요청
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents=[image, "이 이미지를 자세히 설명해 주세요."],
    config=generation_config
)

print(response.text)
```

**이미지 입력 방식**

| 방식 | 설명 | 권장 상황 |
|------|------|----------|
| PIL.Image 객체 | `Image.open()`으로 로드 | 20MB 미만, 가장 간단 |
| bytes + MIME | `types.Part.from_bytes()` | 메모리 기반 처리 |
| 파일 업로드 | `client.files.upload()` | 20MB 이상 대용량 |

### 3.2 로컬 모델 기반 VLM

GPU 환경에서 직접 VLM 모델 실행. API 비용 없음, 데이터 보안 유지.

#### 3.2.1 Qwen3-VL (Alibaba)

> ⚠️ **2025년 5월 기준 최신 모델 정보** — HuggingFace에서 최신 버전 확인 권장

Alibaba에서 개발한 오픈소스 VLM. OCR, 문서 이해, 한국어 지원 우수.
Qwen3-VL은 MoE(Mixture of Experts) 아키텍처를 채택하여 효율성 대폭 향상.

**특징**
- **다양한 크기**: 8B / 30B(MoE) / 235B(MoE) 파라미터
- **MoE 아키텍처**: 30B-A3B는 30B 파라미터 중 3B만 활성화하여 효율적 추론
- **Thinking 버전**: 추론 강화 모델 별도 제공 (복잡한 분석에 적합)
- **OCR 최강**: 문서, 표, 차트 텍스트 추출에 강점
- **한국어 지원**: 한국어 이미지 설명 생성 가능
- **동적 해상도**: 이미지 크기에 따른 자동 토큰 조절

**시스템 요구사항**

| 항목 | 최소 | 권장 |
|------|------|------|
| GPU VRAM | 8GB | 16GB 이상 |
| RAM | 16GB | 32GB 이상 |
| 저장공간 | 20GB | 30GB 이상 |
| CUDA | 12.1+ | 12.4+ |

**핵심 코드**

```python
from transformers import Qwen2VLForConditionalGeneration, AutoProcessor
from qwen_vl_utils import process_vision_info
import torch

# 모델 로드 (8-bit 양자화 적용)
from transformers import BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
    load_in_8bit=True,
    llm_int8_threshold=6.0
)

# Qwen3-VL 모델 로드 (2025년 5월 기준 최신)
model = Qwen2VLForConditionalGeneration.from_pretrained(
    "Qwen/Qwen3-VL-8B-Instruct",     # 사전학습된 모델 ID (HuggingFace Hub)
    torch_dtype=torch.float16,        # 숫자를 절반 크기로 저장해 GPU 메모리 절약
    device_map="auto",                # GPU/CPU 자동 분배 (accelerate 라이브러리 활용)
    quantization_config=quantization_config  # 8비트 양자화 설정 적용
)

processor = AutoProcessor.from_pretrained("Qwen/Qwen3-VL-8B-Instruct")

# 메시지 구성
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "image": "image.jpg"},           # 이미지 입력
            {"type": "video", "video": "video.mp4", "fps": 1}, # 비디오 입력 (fps: 초당 추출 프레임 수)
            {"type": "text", "text": "이 이미지와 비디오를 자세히 설명해 주세요."}
        ]
    }
]

# 입력 처리
text = processor.apply_chat_template(
    messages,                    # 대화 메시지 리스트
    tokenize=False,              # 토큰화하지 않고 문자열로 반환
    add_generation_prompt=True   # 템플릿 끝에 "assistant:" 토큰 추가 (모델이 답변 생성 시작)
)
# messages에서 이미지/비디오 경로를 찾아 실제 데이터로 로드
image_inputs, video_inputs = process_vision_info(messages)
inputs = processor(
    text=[text],
    images=image_inputs,
    videos=video_inputs,
    return_tensors="pt"
).to(model.device)

# 생성
generated_ids = model.generate(**inputs, max_new_tokens=1024)

# 토큰 ID → 텍스트 변환
# generated_ids 구조: [입력 토큰들 | 새로 생성된 토큰들]
# 예) 입력 100토큰 + 생성 50토큰 = 총 150토큰
#     generated_ids.shape = (1, 150)
#     inputs.input_ids.shape[1] = 100
#     generated_ids[:, 100:] → 인덱스 100부터 끝까지 = 생성된 50토큰만 추출
output_text = processor.batch_decode(
    generated_ids[:, inputs.input_ids.shape[1]:],  # [:, 입력길이:] → 생성된 토큰만 추출
    skip_special_tokens=True                        # <pad>, <eos> 등 특수 토큰 제거
)[0]  # batch_decode는 리스트 반환 → 첫 번째 결과 추출

print(output_text)
```

**모델 크기별 비교** (2025년 5월 기준)

| 모델 | 파라미터 | 활성 파라미터 | VRAM (FP16) | VRAM (8-bit) | 용도 |
|------|----------|--------------|-------------|--------------|------|
| Qwen3-VL-8B | 8B | 8B | ~18GB | ~10GB | 로컬 실행 가능, 균형 잡힌 성능 |
| Qwen3-VL-30B-A3B | 30B | 3B (MoE) | ~35GB | ~18GB | 효율적 추론, 고품질 분석 |
| Qwen3-VL-235B-A22B | 235B | 22B (MoE) | ~250GB | ~125GB | 최고 성능 (다중 GPU) |

> 💡 **MoE(Mixture of Experts)**: 전체 파라미터 중 일부만 활성화하여 추론 효율성 향상.
> 예) 30B-A3B는 30B 파라미터 중 3B만 활성화하여 8B급 속도로 30B급 품질 제공.

### 3.3 방식별 비교 정리

| 항목 | Cloud API (Gemini) | 로컬 모델 (Qwen3-VL) |
|------|-------------------|----------------------|
| **설치** | 불필요 | Python 환경 + GPU 드라이버 |
| **비용** | API 호출 당 과금 | 초기 설치 후 무료 |
| **성능** | 높음 (최신 모델) | 모델 크기에 따라 상이 |
| **속도** | 네트워크 의존 | 로컬 GPU 성능 의존 |
| **데이터 보안** | 외부 전송 | 로컬 처리 (보안 우수) |
| **오프라인** | 불가 | 가능 |
| **커스터마이징** | 제한적 | 파인튜닝 가능 |

**선택 가이드**

| 상황 | 권장 방식 |
|------|----------|
| 빠른 프로토타이핑 | Cloud API |
| API 비용 절감 필요 | 로컬 모델 |
| 민감한 데이터 처리 | 로컬 모델 |
| 인터넷 없는 환경 | 로컬 모델 |
| 최고 품질 필요 | Cloud API (최신 모델) |
| 대량 배치 처리 | 로컬 모델 |
