## 1. 개요 (Overview)

### 1.1 Function Calling 정의

LLM이 외부 시스템(API, 데이터베이스, 도구)과  
상호작용할 수 있도록 하는 기능.  
모델이 사용자 요청을 분석하여 적절한 함수 호출 필요 여부를 판단하고,  
필요시 호출할 함수와 인자를 JSON 형태로 반환.

**핵심 포인트**: 모델은 함수를 직접 실행하지 않음.  
어떤 함수를 어떤 인자로 호출할지 결정만 하며,  
실제 실행은 애플리케이션이 담당.

### 1.2 Function Calling의 필요성

#### LLM 단독 사용의 한계

| 한계 | 설명 |
|------|------|
| **정보 단절** | 학습 데이터 이후 정보 접근 불가 |
| **실행 불가** | 생각만 가능, 실제 행동 불가 |
| **단일 턴** | 복잡한 작업의 단계적 수행 어려움 |

#### Function Calling으로 해결

| 한계 | 해결 방법 |
|------|----------|
| 정보 단절 | 웹 검색, DB 조회 함수 호출 |
| 실행 불가 | 외부 API/시스템 제어 함수 호출 |
| 단일 턴 | 반복 호출로 다단계 작업 수행 |

Function Calling은 **멀티에이젼트 시스템의 핵심 메커니즘**.  
LLM이 "생각만 하는 존재"에서 "실제 행동하는 Agent"로 전환되는 기반 기술.

> 멀티에이젼트 시스템에 대한 자세한 내용은 [멀티에이젼트 시스템 가이드](https://github.com/cna-bootcamp/aistudy/blob/main/agentic-ai/reference/mas.md#2-%EB%A9%80%ED%8B%B0%EC%97%90%EC%9D%B4%EC%A0%BC%ED%8A%B8-%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98) 참조.

### 1.3 용어 비교

| OpenAI | Claude | Gemini |
|--------|--------|--------|
| Tool Calling | Tool Use | Function Calling |

동일한 기능을 각 벤더가 다른 이름으로 부름.  
본 문서에서는 "Function Calling"으로 통일.

### 1.4 주요 사용 사례

| 사용 사례 | 설명 | 예시 |
|----------|------|------|
| **정보 조회** | 외부 데이터 소스 접근 | 날씨 API, DB 조회, 검색 |
| **기능 확장** | 모델 능력 보완 | 계산기, 차트 생성, 코드 실행 |
| **작업 실행** | 외부 시스템 제어 | 일정 예약, 이메일, 결제 |
| **데이터 추출** | 구조화된 출력 생성 | 엔티티 추출, 분류 |

## 2. 공통 워크플로우

모든 LLM의 Function Calling은 동일한 5단계 흐름을 따름.

```
┌────────────────────────────────────────────────────────┐
│  1. 도구 정의      사용 가능한 함수들을 스키마로 정의  │
│         ↓                                              │
│  2. 요청 전송      사용자 메시지 + 도구 정의를 전송    │
│         ↓                                              │
│  3. 모델 판단      모델이 함수 호출 필요 여부 결정     │
│         ↓                                              │
│  4. 함수 실행      애플리케이션에서 실제 함수 실행     │
│         ↓                                              │
│  5. 결과 반환      함수 결과 전달 → 최종 응답 생성     │
└────────────────────────────────────────────────────────┘
```

### 2.1 도구 정의

함수 이름, 설명, 파라미터를 JSON 스키마로 정의.  
모델이 함수 호출 여부와 인자를 결정하는 기준이 됨.

#### Claude

```python
tools = [{
    "name": "get_weather",
    "description": "지정된 위치의 현재 날씨 조회",
    "input_schema": {  # parameters 대신 input_schema 사용
        "type": "object",
        "properties": {
            "location": {
                "type": "string",
                "description": "도시 이름 (예: Seoul, Tokyo)"
            },
            "unit": {
                "type": "string",
                "enum": ["celsius", "fahrenheit"],
                "description": "온도 단위"
            }
        },
        "required": ["location"]
    }
}]
```

#### Gemini

```python
from google.genai import types

tools = [types.Tool(
    function_declarations=[types.FunctionDeclaration(
        name="get_weather",
        description="지정된 위치의 현재 날씨 조회",
        parameters=types.Schema(
            type=types.Type.OBJECT,
            properties={
                "location": types.Schema(
                    type=types.Type.STRING,
                    description="도시 이름 (예: Seoul, Tokyo)"
                ),
                "unit": types.Schema(
                    type=types.Type.STRING,
                    enum=["celsius", "fahrenheit"],
                    description="온도 단위"
                )
            },
            required=["location"]
        )
    )]
)]
```

#### OpenAI

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "지정된 위치의 현재 날씨 조회",
        "parameters": {
            "type": "object",
            "properties": {
                "location": {
                    "type": "string",
                    "description": "도시 이름 (예: Seoul, Tokyo)"
                },
                "unit": {
                    "type": "string",
                    "enum": ["celsius", "fahrenheit"],
                    "description": "온도 단위"
                }
            },
            "required": ["location"]
        },
        "strict": True  # 엄격 모드 (선택)
    }
}]
```

#### 도구 정의 모범 사례

| 항목 | 권장 사항 |
|------|----------|
| **이름** | 명확하고 설명적인 snake_case 또는 camelCase |
| **설명** | 함수의 목적, 사용 시점, 반환값을 상세히 기술 |
| **파라미터** | 용도, 형식, 예시를 description에 포함 |
| **타입** | 구체적인 타입 사용 (string보다 enum 선호) |
| **필수값** | required 배열에 필수 파라미터 명시 |
| **개수** | 20개 미만 함수 권장 (토큰 효율성) |

### 3.1 옵션 비교

| 동작 | 설명 | OpenAI | Claude | Gemini |

| **조기 취소** | 잘못된 함수 호출 감지 시 중간에 취소하여 비용 절감 |
| **메모리 효율성** | 대용량 응답을 청크 단위로 처리 |

#### 모델별 지원 현황

| 항목 | OpenAI | Claude | Gemini |
|------|--------|--------|--------|
| 지원 | 정식 지원 | 베타 | 지원 |
| 이벤트 | `function_call_arguments.delta` | 세밀한 파라미터 스트리밍 | - |

#### Claude

```python
import anthropic

client = anthropic.Anthropic()

# 스트리밍 요청
with client.messages.stream(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    tools=tools,
    messages=[{"role": "user", "content": "서울 날씨 어때?"}]
) as stream:
    for event in stream:
        if event.type == "content_block_start":
            if event.content_block.type == "tool_use":
                print(f"함수 호출 시작: {event.content_block.name}")
        elif event.type == "content_block_delta":
            if event.delta.type == "input_json_delta":
                # 함수 인자가 청크 단위로 전달
                print(event.delta.partial_json, end="", flush=True)
```

##### Context-Free Grammar(CFG)를 통한 출력 제약

```python
start: expr
expr: term (SP ADD SP term)* -> add
    | term
term: factor (SP MUL SP factor)* -> mul
    | factor
factor: INT
SP: " "
ADD: "+"
MUL: "*"
%import common.INT
"""

response = client.responses.create(
    model="gpt-5",
    input="math_exp 도구로 4 더하기 4를 표현해줘",
```

#### 추론 모델 (o3, o4-mini, GPT-5)

강화학습으로 훈련된 모델로, 응답 전 내부적으로 **Chain of Thought(CoT)** 를 생성.  
"생각한 후 답변"하여 복잡한 문제에서 정확도 향상.

##### 일반 모델과의 차이

| 항목 | 추론 모델 (o-series, GPT-5) | 일반 모델 (GPT-4o) |
|------|---------------------------|-------------------|
| 내부 프로세스 | 숨겨진 CoT 토큰 생성 | 직접 응답 |
| 지연 시간 | 높음 (더 오래 생각) | 낮음 |
| 비용 | 높음 | 낮음 |
| 적합한 작업 | 복잡한 다단계 작업 | 단순 명확한 작업 |

##### 목적: 왜 Function Calling에서 추론이 필요한가?

1. **도구 선택 개선**: CoT 내에서 언제, 어떤 도구를 사용할지 더 정확하게 판단
2. **다단계 계획**: 이전 도구 결과에 따라 다음 호출을 결정하는 에이전트 워크플로우
3. **성능 향상**: SWE-bench에서 추론 항목 포함 시 ~3% 정확도 향상
4. **환각 감소**: 실행 불가능한 도구 호출을 "약속"하는 현상 감소

##### 사용 사례

| 사용 사례 | 추론이 도움이 되는 이유 |
|----------|----------------------|
| 법률 문서 검토 | 여러 계약서 종합, 조항 식별, 정책 적용 |
| 재무 분석 | 복잡한 시나리오의 주주 지분 영향 계산 |
| 멀티 에이전트 | "플래너" 모델이 각 작업에 맞는 "실행자" 모델 선택 |
| 코드 리뷰 | 여러 파일의 변경 사항 이해, 미묘한 버그 감지 |
| 고객 서비스 | 복잡한 문제 분류, 반품 정책 정확히 적용 |

##### 사용 예시

```python
from openai import OpenAI
import json

client = OpenAI()

tools = [{
    "type": "function",
    "name": "get_weather",
    "description": "좌표의 현재 온도 조회",
    "parameters": {
        "type": "object",
        "properties": {
            "latitude": {"type": "number"},
            "longitude": {"type": "number"}
        },
        "required": ["latitude", "longitude"]
    }
}]

# 추론 설정과 함께 요청
response = client.responses.create(
    model="o4-mini",
    input=[{"role": "user", "content": "파리 날씨 어때?"}],
    tools=tools,
    reasoning={
        "effort": "low",      # "low" | "medium" | "high"
        "summary": "auto"     # 추론 요약 반환
    }
)

# 응답에서 추론 항목과 함수 호출 분리
reasoning_items = [r for r in response.output if r.type == 'reasoning']
function_calls = [r for r in response.output if r.type == 'function_call']

# 추론 요약 출력
if reasoning_items and reasoning_items[0].summary:
    print("추론:", reasoning_items[0].summary[0].text)

# 함수 호출 처리
if function_calls:
    tool_call = function_calls[0]
    args = json.loads(tool_call.arguments)
    result = get_weather(args["latitude"], args["longitude"])
    
    # 추론 항목 포함하여 후속 요청 (컨텍스트 유지)
    context = list(response.output)
    context.append({
        "type": "function_call_output",
        "call_id": tool_call.call_id,
        "output": result
    })
    
    final = client.responses.create(
        model="o4-mini",
        input=context,
        tools=tools
    )
    print(final.output_text)
```

#### Tool Runner

SDK에서 도구 실행을 자동화하는 솔루션.  
수동 도구 호출 루프 대신 간단한 이터레이터로 처리.

##### 목적

- 도구 호출 루프 자동화 (50줄+ 코드 → 5줄)
- 상태 관리, 에러 처리, 타입 검증 자동화
- 장기 실행 에이전트 작업을 위한 자동 컨텍스트 압축

##### 지원 SDK

| SDK | 언어 | 상태 |
|-----|------|------|
| `anthropic-sdk-python` | Python | 베타 |
| `anthropic-sdk-typescript` | TypeScript | 베타 |
| `anthropic-sdk-ruby` | Ruby | 베타 |

##### 사용 사례

| 사용 사례 | 설명 |
|----------|------|
| 장기 실행 에이전트 | 여러 항목 순차 처리 (고객 서비스 티켓, 문서 분석) |
| 다단계 워크플로우 | 여러 도구 호출이 필요한 작업 |
| 배치 처리 | 도구를 사용한 대량 항목 처리 |

##### 수동 구현 vs Tool Runner 비교

**수동 구현** (50줄+):
```python
# 1. Claude에 프롬프트 전송
# 2. tool_use 블록 확인
# 3. JSON 파싱
# 4. 함수 실행
# 5. 결과를 메시지 히스토리에 추가
# 6. Claude 재호출
# 7. 텍스트 응답까지 반복
# 8. 에러 처리...
```

**Tool Runner** (5줄):
```python
for message in runner:
    print(message.content[0].text)
```

##### Python 예시

```python
import anthropic
from anthropic import beta_tool

client = anthropic.Anthropic()

# 데코레이터로 도구 정의
@beta_tool
def get_weather(location: str, unit: str = "celsius") -> str:
    """지정된 위치의 현재 날씨 조회.
    
    Args:
        location: 도시 이름 (예: Seoul, Tokyo)
        unit: 온도 단위 (celsius 또는 fahrenheit)
    """
    return '{"temperature": "20°C", "condition": "맑음"}'

@beta_tool
def calculate_sum(a: int, b: int) -> str:
    """두 숫자를 더합니다.
    
    Args:
        a: 첫 번째 숫자
        b: 두 번째 숫자
    """
    return str(a + b)

# Tool Runner 사용
runner = client.beta.messages.tool_runner(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    tools=[get_weather, calculate_sum],
    messages=[{
        "role": "user",
        "content": "서울 날씨 어때? 그리고 15 + 27은?"
    }]
)

# 메시지 이터레이션 (도구 호출 루프 자동 처리)
for message in runner:
    print(message.content[0].text)

# 또는 최종 메시지만 가져오기
# final_message = runner.until_done()
```

### 5.3 Gemini 고유 기능

> **중요: Function Response의 role 설정**
> 
> 수동으로 Function Calling을 구현할 때, Function Response의 role은 반드시 `"tool"`을 사용해야 합니다.
> 
> ```python
> # 올바른 코드
> types.Content(role="tool", parts=[function_response_part])
> 
> # 잘못된 코드 - API 응답이 멈춤!
> types.Content(role="user", parts=[function_response_part])
> ```
> 
> 또한 `Part.from_text()`는 키워드 인자를 사용해야 합니다: `Part.from_text(text="...")`

#### 자동 함수 호출 (Python SDK)

Python 함수를 직접 도구로 제공하면  
SDK가 자동으로 스키마 변환, 실행 관리, 응답 처리 수행.  
**"함수만 주면 알아서 처리"** 철학.

##### 목적

- 도구 호출 루프 자동화 (수동 구현 불필요)
- JSON 스키마 작성 불필요 (docstring/type hint에서 자동 추론)
- 함수 실행 및 결과 반환 자동 처리

##### 사용 예시

```python
from google import genai

def get_weather(location: str, unit: str = "celsius") -> dict:
    """지정된 위치의 현재 날씨 조회.
    
    Args:
        location: 도시 이름 (예: Seoul, Tokyo)
        unit: 온도 단위 (celsius 또는 fahrenheit)
    
    Returns:
        날씨 정보를 담은 딕셔너리
    """
    return {"temperature": 25, "condition": "sunny"}

client = genai.Client()

# 함수를 직접 전달 → SDK가 스키마 자동 생성 + 실행 관리
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="서울 날씨 어때?",
    config={"tools": [get_weather]}  # 함수 그대로 전달
)

print(response.text)
# SDK가 자동으로:
# 1. docstring/type hint에서 함수 스키마 생성
# 2. 모델이 함수 호출 결정 시 자동 실행
# 3. 결과를 모델에 전달하여 최종 응답 생성
```

##### 지원 타입

`int`, `float`, `bool`, `str`, `list[AllowedType]`, `pydantic.BaseModel`

##### Claude Tool Runner와 비교

Gemini 자동 함수 호출과 Claude Tool Runner는 동일한 목적(도구 호출 루프 자동화)을 가지지만  
구현 철학과 세부 기능이 다름.

| 항목 | Gemini 자동 함수 호출 | Claude Tool Runner |
|------|---------------------|-------------------|
| **스키마 생성** | docstring/type hint에서 **자동 추론** | `@beta_tool` 데코레이터 필요 |
| **코드 간결성** | 더 간단 (함수만 전달) | 데코레이터 + 이터레이터 패턴 |
| **컨텍스트 압축** | ❌ 없음 | ✅ `compaction_control` 옵션 |
| **에러 처리** | 예외 발생 시 중단 | `is_error: true`로 모델에 전달 |
| **SDK 지원** | Python만 | Python, TypeScript, Ruby |
| **철학** | "함수만 주면 알아서" | "명시적 정의 + 추가 제어" |

#### 생각 서명 (Thought Signature)

모델의 내부 사고 과정을 암호화하여 멀티턴 대화에서 추론 컨텍스트를 유지하는 기능.  
Stateless API에서 **Chain of Thought를 "저장"하고 "복원"**하는 메커니즘.

##### 정의 및 목적

Gemini API는 **stateless** 설계로, 각 API 호출이 독립적.  
Thought Signature 없이는:
- 모델이 이전 결정의 이유를 잊음
- 다단계 추론이 단절됨
- Function Calling 워크플로우에서 의도가 손실됨

Thought Signature는 **암호화된 토큰**으로 모델의 숨겨진 상태를 캡슐화하여,  
다음 턴에서 정확히 중단된 지점부터 추론 재개 가능.

##### 동작 원리

```
1. 모델이 응답 생성 → thoughtSignature 포함
2. 클라이언트가 서명 수신 (암호화된 불투명 토큰)
3. 다음 요청에 서명을 대화 히스토리에 포함
4. 모델이 서명으로 내부 추론 상태 복원
5. 전체 컨텍스트로 추론 계속
```

##### 사용 사례

| 사용 사례 | 설명 |
|----------|------|
| 다단계 Function Calling | 순차적 도구 호출이 필요한 에이전트 워크플로우 |
| 복잡한 추론 | 수학 문제 해결, 과학 분석, 다턴 논리적 추론 |
| 이미지 생성/편집 | 순차적 이미지 조작, 반복적 디자인 개선 |
| 코드 생성 파이프라인 | 생성 → 실행 → 디버깅 반복 작업 |

##### 지원 모델

| 모델 | Thinking | 서명 지원 | 검증 |
|------|----------|----------|------|
| Gemini 3 Pro/Flash | ✅ | ✅ | **엄격** (필수) |
| Gemini 2.5 Pro/Flash | ✅ | ✅ | 선택 (권장) |

##### 검증 규칙 (Gemini 3)

| 작업 | 검증 | 서명 누락 시 |
|------|------|-------------|
| Function Calling | **엄격** | 400 에러 |
| 이미지 생성/편집 | **엄격** | 400 에러 |
| 텍스트/채팅 | 권장 | 200 OK (품질 저하) |

##### 서명 처리 규칙

| 규칙 | 설명 |
|------|------|
| 원본 유지 | `thoughtSignature`를 원래 Part 내에서 반환 |
| 병합 금지 | 서명 포함 Part와 미포함 Part 병합 불가 |
| 결합 금지 | 두 개의 서명 포함 Parts 결합 불가 |
| 병렬 호출 | 첫 번째 `functionCall` part의 서명만 반환 |
| 순차 호출 | 모든 서명 누적하여 반환 |

##### 코드 예시: SDK 자동 처리 (권장)

```python

    model="gemini-3-pro-preview",
    config={"thinking_level": "HIGH"}
```

```python
import requests

GEMINI_API_KEY = "your-api-key"
MODEL = "gemini-3-pro-preview"

def call_gemini(contents):

    return response.json()

# ⚠️ thoughtSignature가 포함된 part를 그대로 유지해야 함

# Turn 2 - 서명이 추론 컨텍스트 유지
chat_history.append({"role": "user", "parts": [{"text": "x^2 + 6x + 9 = 0은?"}]})
response2 = call_gemini(chat_history)
print(response2["candidates"][0]["content"]["parts"][0]["text"])
```

#### 멀티모달 함수 응답 (Gemini 3)

함수 결과로 이미지, PDF 등 멀티모달 데이터를 반환하여 모델이 분석할 수 있는 기능.

##### 정의 및 목적

Function Calling에서 텍스트가 아닌 **이미지, PDF, 비디오** 등을  
함수 결과로 반환하여 모델이 시각적 콘텐츠로 이해하도록 하는 기능.

**목적**:
- 스크린샷 도구, 이미지 편집기 등의 결과를 모델에 전달
- PDF 보고서 생성 후 모델이 내용 분석
- 차트/다이어그램 생성 후 설명 요청

##### 현재 상태 및 제한 사항

> ⚠️ **중요**: 직접적인 멀티모달 함수 응답은 **제한적으로 지원**.  
> Base64 인코딩 데이터가 **텍스트로 토큰화**되어 이미지로 인식되지 않는 문제 존재.

| 기능 | 상태 |
|------|------|
| 멀티모달 입력 | ✅ 완전 지원 |
| 멀티모달 출력 (모델 생성) | ✅ 완전 지원 |
| 멀티모달 함수 응답 | ⚠️ 제한적 (ADK Artifacts 우회 권장) |

##### 지원 MIME 유형

| 카테고리 | 지원 형식 |
|---------|----------|
| 이미지 | `image/png`, `image/jpeg`, `image/webp`, `image/gif` |
| 문서 | `application/pdf`, `text/plain` |
| 비디오 | `video/mp4`, `video/webm`, `video/quicktime` |
| 오디오 | `audio/wav`, `audio/mp3`, `audio/ogg` |

##### 사용 사례

| 사용 사례 | 설명 |
|----------|------|
| 스크린샷 도구 | 화면 캡처 후 모델이 내용 분석 |
| 차트 생성기 | 데이터 시각화 후 모델이 인사이트 설명 |
| PDF 생성 | 보고서 생성 후 모델이 요약 |
| 이미지 편집 | 편집 결과를 모델이 검토 |

##### 권장 접근법: ADK Artifacts 사용

직접 base64 반환 대신 **ADK Artifacts** 시스템 사용 권장.

```
1. 도구가 데이터를 Artifact로 저장
2. artifact_id (문자열) 반환
3. 모델이 artifact_id 수신
4. ADK가 자동으로 적절한 MIME 타입으로 로드
```

##### 코드 예시: 직접 반환 (제한적)

```python
from google import genai
import base64

def generate_chart(data: dict) -> dict:
    """차트 생성 (제한적 접근법)"""
    import matplotlib.pyplot as plt
    
    plt.figure()
    plt.plot(data['x'], data['y'])
    plt.savefig('chart.png')
    
    with open('chart.png', 'rb') as f:
        chart_bytes = f.read()
    
    # ⚠️ 제한: base64가 텍스트로 토큰화됨
    return {
        "chart_data": base64.b64encode(chart_bytes).decode('utf-8'),
        "description": f"차트: {data['title']}"
    }
```

##### 코드 예시: ADK Artifacts 사용 (권장)

```python
from google.adk.tools.tool_context import ToolContext
from google.genai.types import Part
import base64

async def generate_chart_with_artifacts(
    tool_context: ToolContext,
    data: dict
):
    """차트 생성 (권장 접근법)"""
    import matplotlib.pyplot as plt
    import io
    
    plt.figure(figsize=(10, 6))
    plt.plot(data['x'], data['y'])
    plt.title(data['title'])
    
    buf = io.BytesIO()
    plt.savefig(buf, format='png')
    chart_bytes = buf.getvalue()
    
    # ✅ Artifact로 저장
    artifact_name = f"chart_{tool_context.function_call_id}.png"
    await tool_context.save_artifact(
        filename=artifact_name,
        artifact=Part(
            inline_data={
                "mime_type": "image/png",
                "data": chart_bytes
            }
        ),
    )
    
    # ✅ artifact_id만 반환 (작은 문자열)
    return {
        "status": "success",
        "chart_artifact_id": artifact_name,
        "description": f"{len(data['x'])}개 데이터 포인트 차트 생성"
    }
```

## 11. AI 모델별 비교

OpenAI, Claude, Gemini의 Function Calling 구현 방식 비교

### 11.1 도구 정의 방식

#### 비교표

| 항목 | OpenAI | Claude | Gemini |
|------|--------|--------|--------|
| 정의 키 | `parameters` | `input_schema` | `types.Schema` |
| 래퍼 구조 | `type: "function"` | 직접 정의 | `types.Tool` |
| 타입 시스템 | JSON Schema | JSON Schema | `types.Type` enum |

#### OpenAI

`type: "function"` 래퍼와 `parameters` 키 사용

```python
# constants.py → get_openai_tools()
{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "도시의 날씨 조회",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "도시 이름"}
            },
            "required": ["city"]
        }
    }
}
```

#### Claude

래퍼 없이 `input_schema` 키 직접 사용

```python
# constants.py → get_claude_tools()
{
    "name": "get_weather",
    "description": "도시의 날씨 조회",
    "input_schema": {
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "도시 이름"}
        },
        "required": ["city"]
    }
}
```

#### Gemini

`types.Tool`과 `types.FunctionDeclaration` 클래스 사용

```python
# constants.py → get_gemini_tools()
from google.genai import types

types.Tool(
    function_declarations=[
        types.FunctionDeclaration(
            name="get_weather",
            description="도시의 날씨 조회",
            parameters=types.Schema(
                type=types.Type.OBJECT,
                properties={
                    "city": types.Schema(
                        type=types.Type.STRING,
                        description="도시 이름"
                    )
                },
                required=["city"]
            )
        )
    ]
)
```

### 11.2 Function Calling 처리 흐름

#### 비교표

| 단계 | OpenAI | Claude | Gemini |
|------|--------|--------|--------|
| 시스템 프롬프트 | `messages[0]` (role: system) | `system` 파라미터 | `config.system_instruction` |
| 함수 호출 감지 | `message.tool_calls` 존재 | `stop_reason == "tool_use"` | `response.function_calls` 존재 |
| 인자 접근 | JSON 파싱 필요 | 이미 dict | dict() 변환 필요 |
| 호출 식별자 | `tool_call.id` | `block.id` | 함수명으로 매칭 |

#### API 호출

**OpenAI** - 시스템 프롬프트를 messages 배열 첫 번째 요소로 포함

```python

    model="gpt-4o-mini",
    messages=messages,  # system prompt 포함
    tools=TOOLS,
    tool_choice="auto"

```

**Claude** - 시스템 프롬프트를 별도 `system` 파라미터로 전달

```python
response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=4096,
    system=SYSTEM_PROMPT,  # 별도 파라미터
    tools=TOOLS,
    messages=messages
)
```

**Gemini** - `GenerateContentConfig` 내 `system_instruction`으로 전달

```python

    model="gemini-2.0-flash",
    contents=contents,
    config=types.GenerateContentConfig(
        tools=TOOLS,
        system_instruction=SYSTEM_PROMPT
    )

```

#### 함수 호출 감지

**OpenAI** - `tool_calls` 속성 존재 여부로 판단, arguments는 JSON 문자열

```python
# openai/travel_planner.py
if assistant_message.tool_calls:
    for tool_call in assistant_message.tool_calls:
```

**Claude** - `stop_reason`으로 판단, input은 이미 딕셔너리

```python
if response.stop_reason == "tool_use":
    for block in response.content:
        if block.type == "tool_use":

            # 파싱 불필요 - 이미 딕셔너리

```

**Gemini** - `function_calls` 속성 존재 여부로 판단, args는 MapComposite 타입

```python
# gemini/travel_planner.py
if response.function_calls:
```

### 11.4 Streaming 방식

#### 비교표

| 항목 | OpenAI | Claude | Gemini |
|------|--------|--------|--------|
| 활성화 방법 | `stream=True` | `messages.stream()` | `generate_content_stream()` |
| 청크 구조 | `chunk.choices[0].delta` | 이벤트 타입별 처리 | `chunk.text` 직접 접근 |
| 텍스트 접근 | `delta.content` | `delta.text` (text_delta) | `chunk.text` |

**OpenAI** - `stream=True` 파라미터로 활성화, delta에서 content 추출

```python
# openai/streaming/travel_planner.py
stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=TOOLS,
    stream=True
)

for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.content:
        yield delta.content
```

**Claude** - `messages.stream()` 컨텍스트 매니저 사용, 이벤트 타입별 처리

```python
# claude/streaming/travel_planner.py
with client.messages.stream(
    model="claude-sonnet-4-20250514",
    max_tokens=4096,
    system=SYSTEM_PROMPT,
    tools=TOOLS,
    messages=messages
) as stream:
    for event in stream:
        if event.type == "content_block_delta":
            if event.delta.type == "text_delta":
                yield event.delta.text
```

**Claude 이벤트 타입**

| 이벤트 | 설명 |
|--------|------|
| `message_start` | 메시지 시작 (메타데이터) |
| `content_block_start` | 블록 시작 (text/tool_use) |
| `content_block_delta` | 블록 델타 (text_delta/input_json_delta) |
| `content_block_stop` | 블록 종료 |
| `message_delta` | 메시지 델타 (stop_reason) |
| `message_stop` | 메시지 종료 |

**Gemini** - `generate_content_stream()` 메서드 사용, chunk.text 직접 접근

```python
# gemini/streaming/travel_planner.py
stream = client.models.generate_content_stream(
    model="gemini-2.0-flash",
    contents=contents,
    config=types.GenerateContentConfig(
        tools=TOOLS,
        system_instruction=SYSTEM_PROMPT
    )
)

for chunk in stream:
    if chunk.text:
        yield chunk.text
```

### 11.5 Streaming + Function Calling

#### 비교표

| 항목 | OpenAI | Claude | Gemini |
|------|--------|--------|--------|
| Function Call 전달 | 델타로 분할 | 이벤트로 분할 | 전체 한 번에 전달 |
| 조립 방식 | index로 매칭, arguments 누적 | content_block 이벤트로 조립 | 조립 불필요 |
| 감지 시점 | 스트림 완료 후 | 스트림 완료 후 | 청크에서 즉시 |

**OpenAI** - tool_calls가 델타로 분할되어 전송됨 → index로 매칭하여 조립 필요

```python
# openai/streaming/travel_planner.py
tool_calls_data = {}  # index → {id, name, arguments}

for chunk in stream:
    delta = chunk.choices[0].delta
    
    if delta.tool_calls:
        for tc_delta in delta.tool_calls:
            idx = tc_delta.index
            
            # 새 tool_call 초기화
            if idx not in tool_calls_data:
                tool_calls_data[idx] = {"id": "", "name": "", "arguments": ""}
            
            # 델타 값 누적
            if tc_delta.id:
                tool_calls_data[idx]["id"] = tc_delta.id
            if tc_delta.function and tc_delta.function.name:
                tool_calls_data[idx]["name"] = tc_delta.function.name
            if tc_delta.function and tc_delta.function.arguments:
                tool_calls_data[idx]["arguments"] += tc_delta.function.arguments
```

**Claude** - tool_use 블록이 이벤트로 분할됨 → 이벤트 타입별로 조립 필요

```python
# claude/streaming/travel_planner.py
tool_use_blocks = {}  # index → {id, name, input_json}
current_block_index = 0

for event in stream:
    # 블록 시작 - tool_use 블록 초기화
    if event.type == "content_block_start":
        if event.content_block.type == "tool_use":
            tool_use_blocks[event.index] = {
                "id": event.content_block.id,
                "name": event.content_block.name,
                "input_json": ""
            }
            current_block_index = event.index
    
    # 블록 델타 - input_json 누적
    elif event.type == "content_block_delta":
        if event.delta.type == "input_json_delta":
            tool_use_blocks[current_block_index]["input_json"] += \
                event.delta.partial_json
```

**Gemini** - function_calls가 전체로 한 번에 전달됨 → 조립 불필요

```python
# gemini/streaming/travel_planner.py
collected_function_calls = None

for chunk in stream:
    # function_calls는 전체가 한 번에 전달
    if chunk.function_calls:
        collected_function_calls = chunk.function_calls
        break  # function_calls 있으면 텍스트 스트리밍 없음
    
    if chunk.text:
        yield chunk.text
```

#### 스트리밍 중 텍스트 출력 시점

첫 번째 스트림에서 function_calls 여부를 알 수 없으므로,  
텍스트를 즉시 출력하면 함수 실행 전에 출력되는 문제 발생

**해결 방법**: 첫 번째 스트림에서는 텍스트 수집만 하고,  
function_calls가 없을 때만 yield

```python
# Claude/Gemini 공통 패턴
collected_text = []

for chunk in stream:
    if has_function_calls(chunk):
        # function_calls 처리
        break
    
    # 텍스트 수집만 (yield 하지 않음)
    if chunk.text:
        collected_text.append(chunk.text)

# function_calls가 없으면 수집한 텍스트 출력
if not function_calls:
    for text in collected_text:
        yield text
    return

# function_calls가 있으면 함수 실행 후 두 번째 스트림에서 출력
```
