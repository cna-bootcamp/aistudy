# 팀 협업

n8n Cloud에서 팀과 협업하고 워크플로우를 공유하는 방법

## 협업 개요

n8n Cloud는 팀 협업을 위한 다양한 기능 제공:
- 사용자 관리 및 역할 기반 접근 제어
- 워크플로우 공유 및 권한 관리
- 자격 증명 공유
- 프로젝트 기반 조직화
- 실시간 협업

## 사용자 역할

### Owner (소유자)
**권한:**
- 모든 관리 기능 접근
- 사용자 추가/제거
- 결제 및 플랜 관리
- 워크스페이스 삭제
- 모든 워크플로우 및 자격 증명 접근

**사용 사례:**
- 조직의 관리자
- 결제 책임자

### Admin (관리자)
**권한:**
- 사용자 관리 (Owner 제외)
- 워크플로우 및 자격 증명 전체 접근
- 설정 변경
- 감사 로그 조회

**제한:**
- 워크스페이스 삭제 불가
- Owner 역할 변경 불가
- 결제 정보 변경 제한

**사용 사례:**
- 기술 리더
- 팀 관리자

### Member (멤버)
**권한:**
- 워크플로우 생성 및 편집
- 공유된 자격 증명 사용
- 자신의 워크플로우 관리
- 공유된 프로젝트 접근

**제한:**
- 사용자 관리 불가
- 전역 설정 변경 불가
- 타인의 개인 워크플로우 접근 불가

**사용 사례:**
- 일반 개발자
- 워크플로우 제작자

## 사용자 초대 및 관리

### 사용자 초대
```
1. Settings > Users 이동
2. "Invite User" 버튼 클릭
3. 초대 정보 입력:
   - Email: 초대할 사용자 이메일
   - Role: Owner/Admin/Member 선택
   - Projects: 초기 프로젝트 할당 (선택사항)
4. "Send Invitation" 클릭
5. 초대 이메일 자동 발송
```

### 초대 수락
```
수신자 측:
1. 초대 이메일 확인
2. "Accept Invitation" 링크 클릭
3. n8n 계정 생성 또는 로그인
4. 워크스페이스 접근 권한 획득
```

### 역할 변경
```
1. Settings > Users에서 사용자 선택
2. Role 드롭다운 클릭
3. 새 역할 선택
4. 변경 즉시 적용
```

### 사용자 제거
```
1. Settings > Users에서 사용자 선택
2. "Remove" 버튼 클릭
3. 확인 대화상자:
   - 사용자의 개인 워크플로우 처리 선택
   - 삭제 또는 다른 사용자에게 이전
4. "Confirm" 클릭
```

## 워크플로우 공유

### 공유 설정
```
1. 워크플로우 열기
2. 우측 상단 "Share" 버튼 클릭
3. 공유 옵션 선택:
   - Private: 소유자만 접근
   - Shared with specific users: 특정 사용자와 공유
   - Shared with project: 프로젝트 멤버 전체 공유
   - Public: 워크스페이스 전체 공유
4. 권한 레벨 설정:
   - View: 보기만 가능
   - Edit: 편집 가능
   - Owner: 소유자 권한
```

### 사용자별 공유
```
1. Share 대화상자에서 "Add User" 클릭
2. 사용자 이름 또는 이메일 입력
3. 권한 레벨 선택
4. "Add" 클릭
5. 사용자에게 알림 발송
```

### 공유 링크
```
1. Share 대화상자에서 "Create Link" 클릭
2. 링크 설정:
   - Expiration: 만료 기간 설정
   - Password: 비밀번호 보호 (선택사항)
   - Permissions: View 또는 Edit
3. 링크 복사 및 공유
```

## 자격 증명 공유

### 공유 가능한 자격 증명 생성
```
1. Credentials 메뉴 이동
2. "New Credential" 클릭
3. 자격 증명 유형 선택
4. 인증 정보 입력
5. "Sharing" 섹션에서:
   - Share with: 공유 대상 선택
   - Permissions: 사용 권한만 또는 편집 권한
6. Save
```

### 자격 증명 접근 제어
```
Owner/Admin:
- 모든 자격 증명 조회 가능
- 공유 설정 변경 가능

Member:
- 공유된 자격 증명 사용 가능
- 개인 자격 증명 생성 가능
- 타인의 개인 자격 증명 접근 불가
```

## 프로젝트 기반 협업

### 프로젝트 생성
```
1. 좌측 사이드바에서 "Projects" 클릭
2. "New Project" 버튼
3. 프로젝트 정보 입력:
   - Name: 프로젝트 이름
   - Description: 설명
   - Members: 팀 멤버 추가
4. Create
```

### 프로젝트에 워크플로우 추가
```
방법 1: 새 워크플로우 생성 시
- Project 드롭다운에서 프로젝트 선택

방법 2: 기존 워크플로우 이동
- 워크플로우 설정에서 Project 변경
```

### 프로젝트 멤버 관리
```
1. Projects > 프로젝트 선택 > Settings
2. Members 탭
3. "Add Member" 클릭
4. 사용자 선택 및 역할 부여:
   - Viewer: 조회만 가능
   - Editor: 편집 가능
   - Admin: 프로젝트 관리 가능
```

## 실시간 협업

### 동시 편집
```
- 여러 사용자가 동시에 워크플로우 편집 가능
- 실시간 커서 및 사용자 표시
- 자동 변경 사항 동기화
- 충돌 방지 메커니즘
```

### 활동 알림
```
알림 유형:
- 워크플로우 공유 알림
- 댓글 및 멘션
- 워크플로우 실행 실패
- 권한 변경 알림
```

### 댓글 및 협업
```
1. 워크플로우 내 노드 선택
2. "Add Comment" 클릭
3. 댓글 작성 및 멘션 (@사용자명)
4. Post
5. 멘션된 사용자에게 알림 발송
```

## 버전 관리 및 협업

### Source Control 통합
```
1. Settings > Source Control
2. Git 리포지토리 연결
3. 브랜치 전략 설정:
   - main: 프로덕션
   - develop: 개발
   - feature/*: 기능 개발
4. 팀원과 브랜치 공유
```

### 변경 사항 추적
```
- 워크플로우 히스토리 조회
- 변경 사항 비교
- 이전 버전 복원
- 변경자 확인
```

## 협업 모범 사례

### 1. 명확한 역할 정의
```
- Owner: 1-2명 (결제 및 최종 권한)
- Admin: 팀 리더급
- Member: 일반 개발자
```

### 2. 프로젝트 구조화
```
프로젝트 구분 기준:
- 비즈니스 도메인별
- 팀별
- 애플리케이션별
```

### 3. 자격 증명 관리
```
- 공유 자격 증명은 최소 권한만 부여
- 민감한 자격 증명은 Owner/Admin만 관리
- 정기적인 자격 증명 감사
```

### 4. 워크플로우 명명 규칙
```
형식: [프로젝트]-[기능]-[환경]
예시:
- CRM-Lead-Sync-Prod
- Marketing-Email-Campaign-Dev
```

### 5. 문서화
```
- 워크플로우 설명 작성
- 노드에 주석 추가
- README 워크플로우 생성
- 온보딩 가이드 유지
```

## 팀 온보딩

### 신규 멤버 온보딩 체크리스트
```
□ 워크스페이스 초대 발송
□ 역할 및 프로젝트 할당
□ 필수 자격 증명 공유
□ 온보딩 문서 공유
□ 첫 워크플로우 함께 만들기
□ 주요 워크플로우 둘러보기
□ 협업 도구 교육
```
