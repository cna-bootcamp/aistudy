# RBAC 역할 유형

## 개요

n8n은 역할 기반 액세스 제어를 통해 프로젝트 수준에서 세 가지 주요 역할 유형 제공.
각 역할은 특정 권한 수준을 가지며 조직의 액세스 제어 요구사항을 충족함.

## 표준 역할 유형

### 1. Project Admin (프로젝트 관리자)
프로젝트에 대한 최고 수준의 액세스 권한:
- 프로젝트 설정 전체 제어
- 사용자 관리 권한
- 역할 할당 및 변경
- 프로젝트 삭제 권한
- 모든 워크플로우 및 자격증명 관리

**주요 권한:**
- 프로젝트 구성 변경
- 사용자 추가 및 제거
- 역할 및 권한 관리
- 리소스 마이그레이션
- 외부 시크릿 통합 설정

### 2. Project Editor (프로젝트 편집자)
워크플로우 및 자격증명 생성 및 수정 권한을 가진 중간 액세스 수준:
- 워크플로우 생성, 편집, 삭제
- 자격증명 생성 및 관리
- 워크플로우 실행 및 모니터링
- 프로젝트 내 리소스 활용

**주요 권한:**
- 워크플로우 개발 및 수정
- 자격증명 설정 및 변경
- 실행 이력 조회
- 프로젝트 리소스 사용

**제한 사항:**
- 프로젝트 설정 변경 불가
- 사용자 관리 권한 없음
- 역할 할당 불가

### 3. Project Viewer (프로젝트 뷰어)
변경 없이 워크플로우 및 실행 내역을 볼 수 있는 읽기 전용 액세스:
- 워크플로우 조회
- 실행 이력 보기
- 프로젝트 현황 모니터링
- 리소스 사용 현황 확인

**주요 권한:**
- 워크플로우 읽기 전용 액세스
- 실행 로그 조회
- 프로젝트 대시보드 보기

**제한 사항:**
- 워크플로우 수정 불가
- 자격증명 생성 및 변경 불가
- 실행 트리거 불가
- 프로젝트 설정 액세스 불가

## 추가 기능

### 사용자 지정 역할 (Custom Roles)
조직은 표준 세 가지 유형을 넘어 맞춤형 역할 생성 가능:
- 조직의 특정 요구사항에 맞춘 권한 조합
- 세밀한 액세스 제어 구현
- 규정 준수 요구사항 충족
- 특수한 워크플로우 관리 역할 정의

### 자격증명 공유
역할에 따른 자격증명 공유 제어:
- 역할별 자격증명 액세스 권한
- 자격증명 사용 범위 제한
- 보안 경계 설정

## 역할 선택 가이드

### Project Admin 할당 기준
- 프로젝트 전체 책임자
- 팀 리더 또는 매니저
- 프로젝트 설정 관리 필요 시

### Project Editor 할당 기준
- 일상적인 워크플로우 개발자
- 자동화 구현 담당자
- 자격증명 관리가 필요한 팀원

### Project Viewer 할당 기준
- 프로젝트 모니터링 담당자
- 감사 및 규정 준수 검토자
- 교육 중인 신규 팀원
- 외부 이해관계자

## 모범 사례

### 최소 권한 원칙
사용자에게 업무 수행에 필요한 최소한의 권한만 부여:
- 업무 요구사항 평가
- 적절한 역할 할당
- 정기적인 권한 검토

### 역할 분리
중요한 작업에 대한 책임 분산:
- 개발과 승인 분리
- 프로덕션 액세스 제한
- 다중 승인 프로세스 구현

### 정기적인 검토
사용자 역할 및 권한의 주기적 점검:
- 분기별 액세스 검토
- 퇴사자 권한 즉시 회수
- 역할 변경에 따른 권한 조정

## 통합

역할 유형은 다음 기능과 통합됨:
- **프로젝트**: 프로젝트별 역할 할당
- **사용자 관리**: 사용자 계정과 역할 매핑
- **자격증명 공유**: 역할 기반 자격증명 액세스 제어
- **감사 로그**: 역할별 활동 추적

## 참고 사항

특정 권한 세부사항은 n8n 버전 및 배포 유형(Cloud/Self-hosted)에 따라 다를 수 있음.
상세한 권한 매트릭스는 공식 문서의 역할 유형 전용 섹션 참조.
