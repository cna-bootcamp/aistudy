# n8n Credential 공유

## 개요

Credential 공유는 팀원들이 동일한 인증 정보를 안전하게 사용할 수 있도록 하는 n8n Enterprise 기능임

## 주요 기능

### 팀 협업
- 여러 사용자가 동일한 Credential 사용
- Credential 정보는 암호화 상태 유지
- 실제 인증 정보는 노출되지 않음

### 접근 제어
- 역할 기반 권한 관리
- 사용 가능 사용자 지정
- 세밀한 권한 설정

## Credential 소유권

### 소유자 (Owner)
- Credential을 생성한 사용자
- 모든 권한 보유
- 공유 설정 관리

### 공유 받은 사용자
- 소유자가 지정한 권한 범위 내에서 사용
- Credential 정보 직접 확인 불가
- 워크플로우에서 사용만 가능

## 공유 설정

### 기본 프로세스

**STEP 1. Credential 선택**
- Credentials 메뉴에서 공유할 Credential 선택
- "Sharing" 또는 "Share" 탭 클릭

**STEP 2. 사용자 추가**
- 공유할 팀원 선택
- 이메일 또는 사용자명으로 검색
- 여러 사용자 동시 추가 가능

**STEP 3. 권한 설정**
- **Use**: Credential 사용만 가능
- **Update**: Credential 수정 가능
- **Share**: 다른 사용자와 재공유 가능

**STEP 4. 저장**
- 설정 저장 시 즉시 적용
- 사용자는 공유된 Credential 목록에서 확인 가능

## 권한 레벨

### Use (사용)
**가능한 작업**:
- 워크플로우에서 Credential 선택 및 사용
- Credential이 설정된 노드 실행

**불가능한 작업**:
- Credential 정보 확인
- Credential 수정
- 공유 설정 변경

### Update (수정)
**Use 권한 포함 + 추가 권한**:
- Credential 정보 수정
- 연결 테스트
- Credential 이름 변경

**제한사항**:
- 삭제는 불가능
- 공유 설정 변경 불가

### Share (공유)
**Update 권한 포함 + 추가 권한**:
- 다른 사용자와 재공유
- 공유 권한 설정
- 공유 해제

**제한사항**:
- Credential 소유권 이전 불가
- 소유자만 삭제 가능

## 공유 범위

### 개인 공유
특정 사용자에게만 공유

**장점**:
- 세밀한 접근 제어
- 보안성 높음

**사용 사례**:
- 민감한 프로덕션 Credential
- 제한된 팀원만 접근 필요한 경우

### 팀 공유
팀 또는 그룹 단위로 공유

**장점**:
- 대규모 팀 관리 용이
- 일괄 권한 부여

**사용 사례**:
- 개발 환경 Credential
- 공통 서비스 계정

### 프로젝트 공유
프로젝트 멤버 전체와 공유

**장점**:
- 프로젝트 범위 내 자동 공유
- 멤버 추가 시 자동 권한 부여

**사용 사례**:
- 프로젝트 전용 서비스 계정
- 팀 프로젝트의 공통 리소스

## 공유 관리

### 공유 상태 확인
- Credential 목록에서 공유 아이콘 표시
- 공유 받은 사용자 수 표시
- 상세 공유 정보 조회

### 공유 수정
- 언제든지 공유 설정 변경 가능
- 권한 레벨 조정
- 사용자 추가/제거

### 공유 해제
- 개별 사용자 공유 해제
- 전체 공유 해제
- 해제 시 즉시 적용

## 사용 시나리오

### 시나리오 1: 개발팀 협업
**상황**:
여러 개발자가 동일한 API를 사용하는 워크플로우 개발

**설정**:
- API Credential을 팀 전체와 공유
- 개발자는 "Use" 권한
- 리드는 "Update" 권한

### 시나리오 2: 환경별 분리
**상황**:
개발/스테이징/프로덕션 환경별 Credential 관리

**설정**:
- 개발 Credential: 개발팀 전체 공유
- 스테이징 Credential: QA팀 포함 공유
- 프로덕션 Credential: 관리자만 접근

### 시나리오 3: 외부 컨설턴트
**상황**:
임시 팀원에게 제한된 접근 제공

**설정**:
- 필요한 Credential만 "Use" 권한으로 공유
- 프로젝트 종료 후 공유 해제
- 감사 로그로 사용 이력 추적

## 제약사항 및 제한

### Enterprise 기능
Credential 공유는 n8n Enterprise 플랜에서만 사용 가능

### 외부 시크릿 제약
외부 시크릿 스토어 연동 시 특정 제약사항 존재:
- 인스턴스 소유자 또는 관리자만 설정 가능
- Infisical 버전 호환성 확인 필요

### 권한 상속
- 하위 권한으로만 재공유 가능
- "Use" 권한으로 받은 사용자는 재공유 불가
- 소유권은 이전 불가

## 모범 사례

### Credential 명명 규칙
- 환경 접두사 사용: `[PROD]`, `[DEV]`, `[STAGING]`
- 서비스명 명시: `Google Sheets - Marketing`
- 용도 표시: `Slack - Notifications`

### 권한 구조
```
소유자 (Admin)
  ↓ Share 권한
팀 리드
  ↓ Update 권한
시니어 개발자
  ↓ Use 권한
주니어 개발자
```

### 정기 검토
- 분기별 공유 권한 검토
- 퇴사자 권한 즉시 제거
- 미사용 Credential 정리

## 문제 해결

### 공유가 안 되는 경우
**원인**:
- Enterprise 라이선스 미적용
- 사용자 권한 부족
- 프로젝트 권한 설정 충돌

**해결책**:
- 라이선스 상태 확인
- 관리자에게 권한 요청
- 프로젝트 설정 검토

### 공유 후 사용 불가
**원인**:
- Credential 자체 오류
- API 키 만료
- 네트워크 문제

**해결책**:
- 소유자가 연결 테스트
- Credential 정보 업데이트
- 네트워크 설정 확인
