# 앱 내 지식 통합 (Integrate Knowledge within Apps)

## 개요

지식 베이스는 LLM 애플리케이션이 정확하고 맥락에 맞는 답변을 제공할 수 있도록 하는 외부 정보 소스로 작동함. 기존 지식
베이스를 모든 Dify 애플리케이션 유형에 연결 가능.

## 지식 통합 애플리케이션 생성

구현 프로세스는 8가지 주요 단계로 구성됨:

1. 지식(Knowledge) 섹션으로 이동하여 파일 업로드
2. 스튜디오에서 새로운 챗봇 애플리케이션 생성
3. 준비된 지식 베이스를 선택하여 컨텍스트 추가
4. 정제된 검색을 위한 메타데이터 필터링 적용
5. 검색 설정 구성
6. 인용(Citation) 기능 활성화
7. 관련 테스트 쿼리를 사용하여 디버그
8. 애플리케이션 게시

## 다중 경로 검색 구성

애플리케이션이 여러 지식 베이스를 사용할 때 검색 모드 구성이 중요함. 시스템은 "컨텍스트에 연결된 모든 지식 베이스를 동시에
쿼리하여 여러 지식 베이스에서 관련 텍스트 청크를 검색"함.

### 검색 설정 옵션

**가중치 점수(Weighted Score) 방식**
이 접근 방식은 내부 점수 매기기를 사용하여 추가 비용을 방지함. 옵션은 다음을 포함:

- 의미론적 검색만(Semantic-only): 임베딩을 사용한 의미 기반 매칭
- 키워드 검색만(Keyword-only): 정확한 용어 매칭
- 두 가지 접근 방식을 결합한 커스텀 가중치 비율

**Rerank 모델 접근 방식**
외부 점수 매기기 시스템이 쿼리와 문서 간의 관련성을 계산하며, API 키가 필요하지만 복잡한 콘텐츠를 더 효과적으로 처리함.

### 조정 가능한 파라미터

- **TopK**: 기본값 3개 청크; 높은 값은 더 많은 콘텐츠 검색
- **점수 임계값(Score Threshold)**: 기본값 0.5의 최소 유사도 요구 사항

## 메타데이터 필터링

필터링은 세 가지 모드로 작동:

- **비활성화(Disabled)**: 필터링 적용 안 함
- **자동(Automatic)**: 쿼리 변수에서 구성 도출(모델 선택 필요)
- **수동(Manual)**: 특정 연산자를 사용한 커스텀 필터 구성

지원되는 필드 유형에는 문자열, 숫자, 날짜가 포함되며, 각각 고유한 연산자(정확한 일치, 포함, 이전/이후 등)를 가짐.

## 주요 결정 요소

검색 방법 간 선택은 쿼리 특성에 따라 달라짐: 정확한 용어는 키워드 강조를 제안하는 반면, 다국어 또는 비정확 쿼리는 의미론적
접근 방식에서 이점을 얻음.
