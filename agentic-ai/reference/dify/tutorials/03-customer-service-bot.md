# 지식 베이스 기반 고객 서비스 봇 (Customer Service Bot)

## 개요

본 가이드는 LLM 컨텍스트 윈도우를 초과하는 질문을 처리하기 위해 지식 베이스를 활용하는 지능형 고객 서비스 봇 구축 방법을 설명함.
이 접근 방식은 의미 수준 검색을 통해 전통적인 키워드 기반 봇의 한계를 해결함.

## 핵심 개념

**컨텍스트 윈도우 (Context Window)**: LLM이 정보를 처리할 때 "볼" 수 있고 참조할 수 있는 텍스트의 범위. 더 큰 윈도우는
더 정확하고 일관된 응답을 가능하게 함.

**임베딩 (Embedding)**: 단어나 문서와 같은 이산 변수를 연속 벡터 표현으로 변환하는 기술.
"의미상 유사한 텍스트의 벡터는 서로 가까이 위치하며, 의미상 반대되는 텍스트의 벡터는 멀리 떨어져 있음."

## 전제 조건

- Dify에서 Chatflow 애플리케이션 생성
- TEXT EMBEDDING을 지원하는 모델 제공자 추가(OpenAI 또는 Cohere 권장)
- 임베딩 작업을 위한 충분한 계정 잔액 확보

## 지식 베이스 생성

**지원되는 데이터 소스:**
- 로컬 문서
- Notion(계정 연동 필요)
- 웹 페이지(Jina 또는 Firecrawl API 필요)

### 구성 설정

**청크 설정 (Chunk Settings)**: Dify는 자동으로 콘텐츠를 단락으로 분할하며, 커스텀 분할 옵션 제공.

**인덱스 방법 (Index Method)**:
- High Quality (토큰 소비)
- Economic (무료)
- 특정 언어를 위한 Q&A 모드

**임베딩 모델 (Embedding Models)**: 사용 사례에 따라 선택(예: 영어는 Cohere의 `embed-english`,
혼합 언어는 `embed-multilingual`).

**검색 설정 (Retrieval Settings)**: 벡터, 전체 텍스트 또는 하이브리드 검색(가장 일반적)의 세 가지 옵션 제공.
하이브리드 검색은 의미적 매칭(70%)과 키워드 매칭(30%) 간의 가중치 조정 지원.

**웹사이트 동기화 (Website Syncing)**: Dify는 최대 50페이지까지 처리함.

### 품질 보증

처리 후 세그먼트 일관성을 수동으로 검증함. 일관성 없는 청크는 검색 정확도를 저하시킴.
키워드 입력으로 Recall Test 기능을 사용하여 검색 정확도 테스트.

## Chatflow 구축

### 질문 분류 노드 (Question Classification Node)

사용자 문의를 분류함(관련 없는 질문, 제품별 쿼리, 기술 설명, 커뮤니티 요청). 정확도를 위해 고품질 LLM 선택.

### 직접 응답 노드 (Direct Reply Node)

LLM 처리가 필요 없는 분류를 처리함. 예시 응답: "죄송합니다, 귀하의 질문에 답변할 수 없습니다. 더 많은 도움이 필요하시면
도움말 문서를 확인하세요."

### 지식 검색 노드 (Knowledge Retrieval Node)

연결된 지식 베이스에서 관련 정보를 쿼리함.

### LLM 노드

검색된 콘텐츠를 적절한 응답으로 구성함. 시스템 프롬프트 구조: "{{context}}를 기반으로 {{user question}}에 답변하세요."

일관된 다중 턴 대화를 위해 LLM 메모리 활성화.

## 고급 기능

**외부 지식 베이스 (External Knowledge Bases)**: API 통합을 통해 AWS Bedrock 및 유사 서비스 연결.

**API 관리 (API Management)**: Dify의 API를 통해 프로그래밍 방식으로 지식 베이스 상태를 추가, 삭제 및 쿼리함.

**웹 임베딩 (Web Embedding)**: 배포 후 코드 임베딩 옵션을 통해 웹 페이지에 챗봇 배포.
