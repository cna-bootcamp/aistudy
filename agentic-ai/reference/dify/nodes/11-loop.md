# Loop (루프)

## 핵심 개념

Loop 노드는 각 주기가 이전 결과를 기반으로 점진적으로 발전하는 반복 workflow를 가능하게 함.
문서에 따르면 루프는 "각 반복과 함께 진화하는 점진적 workflow를 가능하게" 하며, 이는 독립적인 반복 프로세스와 차별화됨.

## Loop vs Iteration 차이점

**Loop 특성:**
- "순차적 처리 - 각 주기는 이전 결과에 의존"
- 변수가 주기 전반에 걸쳐 누적되어 상태 유지
- 콘텐츠 개선 및 문제 해결 시나리오에 이상적

**Iteration 특성:**
- "독립적 처리 - 각 항목이 별도로 처리됨"
- 유사한 작업의 병렬 실행 가능
- 배치 작업 및 대량 데이터 변환에 더 적합

## 구성 요소

시스템은 세 가지 주요 설정 구성 요소를 요구함:

1. **Loop Variables** - "상태를 유지하고 점진적 workflow를 가능하게 하는" 지속적 데이터 구조
2. **Termination Condition** - 종료 기준을 결정하는 표현식 (예: `quality_score > 0.9`)
3. **Safety Limits** - 무한 실행을 방지하는 최대 루프 횟수

문서에 따르면 "루프는 종료 조건이 충족되거나, 최대 횟수에 도달하거나, Exit Loop 노드가 실행될 때 종료됨."

## 실용적인 예제

두 가지 구현 모델이 제공됨: 기본 메커니즘을 보여주는 기본 난수 생성기와, 변수 지속성 및 여러 주기에 걸친 반복적 LLM 향상을 보여주는
고급 시 개선 workflow.
