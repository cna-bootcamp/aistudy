# Agent (에이전트)

## 핵심 목적

Agent node는 LLM이 복잡한 작업 실행을 위해 도구를 자율적으로 제어할 수 있도록 함.
모든 단계를 사전 계획하는 대신, agent는 동적으로 추론하고 반복적으로 사용할 도구를 결정함.

## Agent 전략

**Function Calling**: 네이티브 LLM 기능을 활용하여 도구 정의를 직접 전달함.
"GPT-4, Claude 3.5 및 강력한 function calling을 지원하는 기타 모델에 최적."

**ReAct (Reason + Act)**: 명시적 추론을 통해 모델을 안내하는 구조화된 프롬프트 사용.
이 접근 방식은 "투명한 의사결정을 위한 **Thought → Action → Observation** 주기"를 따름.

## 구성 요소

**모델 선택**: 전략을 지원하는 LLM을 선택함.
더 고급 모델은 복잡한 추론을 처리하지만 반복당 비용이 증가함.

**도구 설정**: 인증 자격 증명, 기능 및 사용 사례를 설명하는 명확한 설명, 적절히 검증된 매개변수가 필요함.

**지시사항**: 자연어 및 업스트림 workflow 변수 참조를 위한 Jinja2 구문을 사용하여 agent의 역할을 정의함.

**실행 제어**: 작업 복잡도에 따라 무한 루프를 방지하기 위한 최대 반복 횟수를 설정함—
간단한 작업은 3-5회 반복이 필요하며 "복잡한 연구는 10-15회가 필요할 수 있음."

**메모리 관리**: TokenBufferMemory는 토큰 소비 대비 컨텍스트 가용성의 균형을 맞추면서 과거 메시지 보존을 제어함.

## 출력 변수

Agent는 최종 답변, 도구 결과, 추론 추적, 반복 횟수, 성공 상태 및 디버깅을 위한 구조화된 로그를 제공함.

## 권장 사례

명확한 도구 설명, 적절한 반복 제한, 제약 조건을 정의하는 상세한 지시사항,
특정 사용 사례 요구사항에 맞춘 메모리 최적화를 강조함.
