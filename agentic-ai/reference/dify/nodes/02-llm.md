# LLM 노드

## 개요

LLM node는 구성된 언어 모델을 통해 텍스트, 이미지 및 문서를 처리함.
구조화된 출력, 컨텍스트 관리 및 멀티모달 입력을 지원하면서 응답을 캡처함.

**핵심 요구사항:** LLM node 사용 전 시스템 설정에서 모델 제공자를 구성해야 함.

## 모델 선택

다양한 제공자 중에서 선택 가능함.
문서에 따르면 "GPT-4와 Claude 3.5는 복잡한 추론을 잘 처리하지만 비용이 더 많이 들며, GPT-3.5 Turbo는 성능과 경제성의 균형을 제공함."
로컬 배포 옵션으로는 Ollama, LocalAI 또는 Xinference 포함.

## 매개변수 및 Temperature

응답 생성은 여러 설정을 통해 제어됨.
Temperature는 0(결정론적 출력)에서 1(창의적 응답) 범위임.
추가 제어 항목으로는 Top P(확률 기반 단어 제한), Frequency Penalty(반복 감소), Presence Penalty(새로운 주제 권장) 포함.
사전 설정 옵션: Precise, Balanced, Creative.

## 프롬프트 구성

채팅 모델은 메시지 역할 사용 (System은 동작, User는 입력, Assistant는 예시),
완성 모델은 텍스트 연속 사용.
변수는 `{{variable_name}}`과 같이 이중 중괄호를 사용하여 참조됨.

## 컨텍스트 변수 및 RAG

외부 지식은 소스 귀속을 유지하면서 컨텍스트 변수를 통해 주입 가능함.
Knowledge Retrieval node 출력이 LLM 컨텍스트 입력에 연결되며, 사용자를 위한 자동 인용 추적 제공.

## 구조화된 출력

특정 데이터 형식을 강제하는 세 가지 구성 방법:
- 시각적 편집기: 간단한 구조용
- JSON 스키마: 복잡한 중첩 객체용
- AI 생성: 자연어 설명용

## 고급 기능

- **메모리:** 대화 내 여러 호출에 걸쳐 컨텍스트 유지
- **파일 처리:** vision 세부 제어(High/Low)를 통한 멀티모달 입력 지원
- **Jinja2 템플릿:** 루프, 조건문 및 복잡한 변환 지원
- **스트리밍:** 텍스트 청크를 실시간 이벤트로 생성
- **오류 처리:** 구성 가능한 재시도 횟수, 간격 및 대체 전략
