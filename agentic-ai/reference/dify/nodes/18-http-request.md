# HTTP Request (HTTP 요청)

## 개요

HTTP Request 노드는 workflow와 외부 API 또는 웹 서비스 간의 연결을 촉진하여
데이터 가져오기, 웹훅 전송, 파일 업로드 및 타사 통합을 가능하게 함.

## 지원되는 HTTP 메서드

**데이터 검색:**
- GET은 수정 없이 서버 데이터를 검색함
- HEAD는 전체 본문 없이 응답 헤더를 얻음

**데이터 제출:**
- POST는 리소스 생성을 위해 데이터를 전송함
- PUT은 기존 리소스를 생성하거나 완전히 교체함
- PATCH는 리소스에 부분 수정을 적용함

**리소스 관리:**
- DELETE는 서버 리소스를 제거함

## 구성 기능

노드는 URL, 헤더, 쿼리 파라미터, 요청 본문 및 인증 메커니즘의 포괄적인 사용자 정의를 허용함.
이전 workflow 노드 변수는 요청 설정 전반에 걸쳐 동적으로 통합될 수 있음.

**변수 통합:** workflow 변수를 참조하기 위해 `{{variable_name}}` 구문을 사용하며,
`{{api_response.data.items[0].id}}`와 같은 중첩 객체 액세스 포함.

**타임아웃 관리:** 구성 가능한 연결, 읽기 및 쓰기 타임아웃이 workflow 지연 및 리소스 고갈을 방지함.

**인증 옵션:**
- 인증 없음
- API Key 인증 (Basic, Bearer 또는 Custom 헤더 변형)

## 요청 및 응답 처리

지원되는 본문 타입에는 JSON, Form Data, Binary (파일 업로드용) 및 Raw Text 형식이 포함됨.

노드는 Content-Disposition 분석, MIME 타입 평가 및 콘텐츠 샘플링을 통해 파일 응답을 자동으로 식별함.
바이너리 콘텐츠는 파일 변수가 되고 텍스트 기반 응답은 데이터로 유지됨.

**응답은 다음에 대한 액세스를 제공함:**
- 응답 본문 콘텐츠
- HTTP 상태 코드
- 헤더 메타데이터
- 파일 변수
- 콘텐츠 크기 정보

## 오류 관리

구성 가능한 재시도 메커니즘은 조정 가능한 간격(최대 5000ms)으로 최대 10회 자동 시도를 지원함.
요청이 실패할 때 대체 workflow 경로가 활성화되어 외부 서비스 사용 불가에도 불구하고 계속 실행됨.

SSL 인증서 검증은 노드별로 구성 가능하며, 외부 API 보안을 유지하면서 자체 서명 인증서를 수용함.
