1 왜 필요할까?

트랜스포머의 어텐션은 문장 속 단어들을 동시에 바라봅니다. 순서를 따라 하나씩 읽는 게 아니에요. 문제는, 어텐션 계산만 놓고 보면 단어 순서를 바꿔도 결과가 똑같다는 점입니다. (이를 "순열 불변"이라고 해요.)

어텐션 입장에서 아래 두 문장은 구별되지 않습니다 👇

개가1번째
고양이를2번째
물었다3번째
고양이가?
개를?
물었다?
⚠️ "개가 고양이를 물었다"와 "고양이가 개를 물었다"는 뜻이 정반대인데, 위치 정보가 없으면 모델은 이 둘을 헷갈립니다.

그래서 각 단어 벡터에 "너는 몇 번째 자리야"라는 정보를 더해서 넣어줍니다. 마치 영화관 좌석에 좌석 번호를 붙이는 것과 같아요. 🎫

2 핵심 아이디어 — 위치마다 고유한 "파도 무늬"

가장 단순한 생각은 "1번, 2번, 3번…" 숫자를 그냥 더하는 것입니다. 하지만 문장이 길어지면 숫자가 너무 커져서(100, 500…) 단어 자체의 의미를 덮어버립니다.

❌ 그냥 번호 더하기

위치 500 → 값이 500. 단어 의미(보통 -1~1)를 압도해 버림.

✅ sin·cos 파도 더하기

값이 항상 -1 ~ 1 사이. 위치가 멀어도 크기가 폭발하지 않음.

트랜스포머는 위치마다 서로 다른 "파도 무늬(sin·cos)"를 만들어 더합니다. 벡터의 각 칸(차원)마다 다른 속도로 출렁이게 해서, 모든 위치가 세상에 하나뿐인 무늬를 갖게 하죠.

💡 비유: 느린 시계바늘(시침)과 빠른 시계바늘(분침·초침)을 여러 개 겹쳐 놓으면, 바늘들의 조합만 보고도 "지금 몇 시 몇 분"인지 딱 하나로 알 수 있죠. 위치 인코딩도 느린 파도 + 빠른 파도를 겹쳐서 위치를 특정합니다.

차원마다 다른 파도 (아래 그래프)

낮은 차원 = 느린 파도(긴 주기), 높은 차원 = 빠른 파도(짧은 주기). 슬라이더로 확인해 보세요.

가로축 = 문장 속 위치(pos)·세로축 = 값(-1~1)

3 sin·cos 공식

위치 pos, 차원 번호 i 에 대해 값을 이렇게 정합니다. 짝수 차원엔 sin, 홀수 차원엔 cos를 씁니다.

PE(pos, 2i) = sin( pos / 100002i/d )
PE(pos, 2i+1) = cos( pos / 100002i/d )
d = 벡터 차원 수(d_model), i = 0,1,2,…
기호뜻직관
pos단어의 위치 (0,1,2,…)몇 번째 좌석인지
i벡터 안 차원 짝의 번호몇 번째 시계바늘인지
100002i/d파도의 주기(느림/빠름)바늘이 도는 속도
🔑 핵심은 100002i/d 부분입니다. 차원 i가 커질수록 분모가 커져 파도가 느려집니다(주기가 길어짐). 그래서 차원마다 속도가 다른 "여러 개의 시계바늘"이 만들어져요.

4 직접 만져보기 — 위치 인코딩 히트맵

실제 pe 표를 그려봅니다. 가로 = 벡터 차원, 세로 = 위치. 칸의 밝기가 그 위치·차원의 값이에요. 노트북 코드가 만드는 표와 똑같은 방식으로 계산합니다.

낮음높음 가로↔ 차원(0…d_model) · 세로↕ 위치(0…max_len)
👀 관찰 포인트: 왼쪽 차원일수록 세로 줄무늬가 넓고 완만(느린 파도), 오른쪽 차원일수록 촘촘(빠른 파도)합니다. 그리고 모든 가로줄(위치)의 무늬가 서로 다릅니다 — 이게 "위치마다 고유한 지문"이라는 뜻이에요.

5 왜 하필 sin·cos일까?

① 값이 안 터진다

항상 -1~1 사이라, 문장이 아무리 길어도 위치값이 단어 의미를 압도하지 않습니다.

② 상대 위치를 담는다

삼각함수 덧셈정리 덕분에 "k칸 떨어진 위치"의 관계를 일정한 회전으로 표현할 수 있어, 모델이 거리(상대 위치)를 배우기 쉽습니다.

③ 학습이 필요 없다

공식으로 바로 계산 → 학습 파라미터가 아닙니다. 그래서 코드에서 register_buffer로 "상수"처럼 등록해요.

④ 안 배운 길이도 OK

학습 때 본 적 없는 더 긴 문장이 와도 공식으로 그냥 값을 만들 수 있습니다(외삽 가능).

6 노트북 코드 한 줄씩 뜯어보기

실습 노트북 example-detailed.ipynb의 PositionalEncoding 클래스입니다.

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=128, dropout=0.1):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(0, max_len).float().unsqueeze(1)
        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)   # 짝수 차원 = sin
        pe[:, 1::2] = torch.cos(pos * div)   # 홀수 차원 = cos
        self.register_buffer("pe", pe.unsqueeze(0))

    def forward(self, x):
        return self.dropout(x + self.pe[:, :x.size(1)])
  1. pe = torch.zeros(max_len, d_model)
    빈 표를 만듭니다. 세로 = 위치 개수, 가로 = 벡터 차원. 여기에 파도무늬를 채워 넣을 거예요.
  2. pos = torch.arange(0, max_len).unsqueeze(1)
    위치 번호 0,1,2,…를 세로 기둥(max_len, 1) 모양으로 세웁니다. 공식의 pos에 해당.
  3. div = exp( arange(0,d,2) · (−log(10000)/d) )
    차원마다 다른 주파수(파도 속도)를 한 번에 계산. 이건 공식의 1 / 100002i/d를 수치적으로 안정하게 계산한 형태예요. (지수·로그로 바꿔 계산하면 오차가 적습니다.)
  4. pe[:, 0::2] = sin(pos*div) / pe[:, 1::2] = cos(pos*div)
    짝수 칸(0,2,4…)엔 sin, 홀수 칸(1,3,5…)엔 cos를 채웁니다. pos*div는 (max_len,1)×(d/2,) 브로드캐스팅으로 (max_len, d/2) 표가 됩니다.
  5. register_buffer("pe", pe.unsqueeze(0))
    이 표는 학습하지 않는 상수이므로 파라미터가 아닌 버퍼로 등록. unsqueeze(0)로 맨 앞에 배치축을 붙여 (1, max_len, d_model) 모양으로 만듭니다. 그래야 나중에 여러 문장(배치)에 한 번에 더할 수 있어요.
  6. return dropout( x + pe[:, :x.size(1)] )
    진짜 사용하는 순간! 입력 임베딩 x (B, S, d_model)에, 위치표에서 현재 문장 길이 S만큼만 잘라 더합니다. 즉 "단어 의미 + 위치 정보"가 완성됩니다. dropout은 학습 안정화용.
🧠 포인트 하나: 위치 정보는 곱하거나 이어붙이는 게 아니라 "더한다"는 것. 임베딩과 같은 공간에서 그냥 합으로 섞이고, 나머지는 모델이 알아서 활용합니다.
